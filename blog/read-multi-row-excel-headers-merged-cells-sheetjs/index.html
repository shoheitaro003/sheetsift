Read multi-row Excel headers with merged cells in SheetJS

2026-11-26

A customer uploads a sales report whose header has two rows: "Q1" is merged across two columns, with "Revenue" and "Cost" under it. SheetJS reads the first row as the column names, so you get keys like __EMPTY, and the second header row arrives as a record.

By the end of this post you will have readGroupedTable(bytes): it finds how many rows the header has from its merged cells, names each column from top to bottom (Q1 Revenue, Q1 Cost), and refuses headers it cannot name with confidence, with the Excel address of the cell to fix. The code is not self-contained: it adds two functions to the module from our post on filling merged cells and uses its readXlsx, fillMerges, isEmpty and isLabel, which also handle merges in the data rows. Every result quoted below is checked by our test file (the tests named mh:) in Node 22 with SheetJS 0.20.3.

The problem

Here is the file. Each merged range is drawn as one cell:

ABCDEF
1Region
(A1:A2)		Rep
(B1:B2)		Q1 (C1:D1)Q2 (E1:F1)
2RevenueCostRevenueCost
3North
(A3:A4)		Ana1006012070
4Bo90508040
5SouthCy70307535

Read the usual way, and then starting at row 2 with the range option:

// Sales.xlsx: "Region" and "Rep" are merged down over A1:A2 and B1:B2,
// "Q1" across C1:D1 and "Q2" across E1:F1, with Revenue and Cost under each.
const sheet = workbook.Sheets[workbook.SheetNames[0]];
const records = XLSX.utils.sheet_to_json(sheet);
records.length;                    // 4  (row 2, the second header row, is read as a record)
Object.keys(records[0]).join(", ");  // 'Q1, __EMPTY, Q2, __EMPTY_1'
const fromRow2 = XLSX.utils.sheet_to_json(sheet, { range: 1 });
Object.keys(fromRow2[0]).join(", "); // '__EMPTY, __EMPTY_1, Revenue, Cost, Revenue_1, Cost_1'

A merged range stores its value in its first (top-left) cell only, so D1 and F1 are empty and SheetJS invents __EMPTY names for them. Starting at row 2 loses "Q1" and "Q2" instead, and the two Revenue columns become Revenue and Revenue_1. Neither tells your column mapping which quarter a number belongs to.

Step 1: read the header

The merges tell you the shape of the header. A label merged across columns is a group label: it says that the columns under it share a name, so the row under it must be part of the header too. A label merged down, like "Region" over A1:A2, just fills the header's height and counts once in the name. A merge with no value is layout, and is ignored.

Add this function to the module from the previous post.

// Reads a header that starts at row index `top` and may have up to maxRows rows.
// A cell merged across columns ("Q1" over C1:D1) is a group label, so the row
// below it is part of the header too. Returns one name per column ("Q1 Revenue"),
// the parts of each name (["Q1", "Revenue"]), the number of header rows, and
// problems. If any problem has refuse: true, the header was not read.
function readHeader(rows, merges, top, origin, maxRows = 3) {
  const excelAddress = (r, c) => XLSX.utils.encode_cell({ r: origin.r + r, c: origin.c + c });
  const valueAt = (r, c) => rows[r]?.[c] ?? "";
  const mergeAt = (r, c) => merges.find((m) => m.top <= r && r <= m.bottom && m.left <= c && c <= m.right);
  // What Excel shows in a cell: for any cell of a merge, the first cell's value.
  const shown = (r, c) => { const m = mergeAt(r, c); return m ? valueAt(m.top, m.left) : valueAt(r, c); };
  // An empty merge is layout, not a label.
  const isGroup = (m) => m !== undefined && m.right > m.left && !isEmpty(valueAt(m.top, m.left));
  const refuse = (list) => ({ depth: 0, columns: [], parts: [], problems: list.map((p) => ({ ...p, refuse: true })) });

  // 1. Count the header rows. A group label needs one row of names under it;
  //    if that row holds a group label too (a year over quarters), one more.
  let depth = 1;
  for (let grown = true; grown; ) {
    grown = false;
    for (const m of merges) {
      if (!isGroup(m) || m.top < top || m.top >= top + depth) continue;
      const needed = m.bottom - top + 2; // the label's rows plus one row of names
      if (needed > depth) { depth = needed; grown = true; }
    }
  }
  const start = excelAddress(top, 0);
  if (depth > maxRows) return refuse([{ range: start, reason: `the header would have ${depth} rows; this code reads at most ${maxRows}` }]);
  // A file that ends inside the header, such as a group label in its last row.
  if (top + depth > rows.length) return refuse([{ range: start, reason: `no data rows under the ${depth}-row header` }]);
  const headerRows = [...Array(depth).keys()].map((i) => top + i);

  // 2. One name per column: the labels from top to bottom, joined with a space.
  //    A label merged down ("Region" over A1:A2) counts once.
  const labelsOf = (c) => {
    const labels = [];
    let previous;
    for (const r of headerRows) {
      const m = mergeAt(r, c);
      if (m !== undefined && m === previous) continue;
      previous = m;
      if (!isEmpty(shown(r, c))) labels.push(String(shown(r, c)).trim());
    }
    return labels;
  };
  const lastColumn = Math.max(0, ...headerRows.map((r) => rows[r].length));
  const parts = [...Array(lastColumn).keys()].map(labelsOf);
  const width = parts.findLastIndex((labels) => labels.length > 0) + 1;
  if (width === 0) return refuse([{ range: start, reason: "the header row has no column names; if the header is lower, pass its row index as headerTop" }]);
  parts.length = width;
  const first = parts.findIndex((labels) => labels.length > 0); // first named column

  // 3. Refuse headers that would give wrong names, before any record is read.
  const problems = [];
  const groups = merges.filter((m) => isGroup(m) && m.top >= top && m.top < top + depth && m.left < width);
  for (const m of groups) {
    const label = JSON.stringify(valueAt(m.top, m.left));
    if (m.left <= first && m.right >= width - 1 && width - first > 1) {
      // Over every named column it would start every name: read it as a title.
      problems.push({ range: m.address, reason: `${label} spans the whole table, so it looks like a title`,
        hint: "pass the row index of the column names as headerTop" });
      continue;
    }
    // Every column under a group label needs a name in a header row below it.
    for (let c = m.left; c <= Math.min(m.right, width - 1); c++) {
      if (headerRows.some((r) => r > m.bottom && !isEmpty(shown(r, c)))) continue;
      problems.push({ range: m.address, reason: `${label} has no column name under it in ${excelAddress(m.bottom + 1, c)}`,
        hint: "type the missing name, or unmerge the label" });
    }
  }
  // Below the first header row, a value may sit under a group label or under empty
  // cells (a name aligned to the bottom row), but not under a plain label: "Ana"
  // under "Name" means this row is data, and the merge that pulled it into the
  // header is a title or layout.
  for (const r of headerRows.slice(1)) {
    const cause = groups.find((g) => g.top < r && g.bottom + 1 >= r);
    const causeText = cause ? cause.address : "a merged cell above it";
    for (let c = 0; c < width; c++) {
      if (isEmpty(valueAt(r, c)) || mergeAt(r, c)) continue;
      const above = headerRows.filter((a) => a < r && !isEmpty(shown(a, c))).pop();
      if (above === undefined || isGroup(mergeAt(above, c))) continue;
      problems.push({ range: excelAddress(r, c),
        reason: `${JSON.stringify(valueAt(r, c))} is under the label ${JSON.stringify(shown(above, c))} (${excelAddress(above, c)}), so row ${origin.r + r + 1} looks like data`,
        hint: `${causeText} made row ${origin.r + r + 1} part of the header. If it is a title, pass the row index of the column names as headerTop; if it is layout, unmerge it; if both cells are one name, type the whole name in one cell` });
    }
  }
  if (problems.length > 0) return refuse(problems);
  // Rows past the header that are all empty do not count as data.
  if (rows.slice(top + depth).every((row) => row.every(isEmpty))) {
    return refuse([{ range: start, reason: `no data rows under the ${depth}-row header` }]);
  }

  // 4. Values hidden under a header merge are not used in any name: report them.
  //    The header is still read, as for hidden values in the data.
  for (const m of merges) {
    for (const r of headerRows) {
      if (r < m.top || r > m.bottom) continue;
      for (let c = m.left; c <= m.right; c++) {
        if ((r === m.top && c === m.left) || isEmpty(valueAt(r, c))) continue;
        problems.push({ range: m.address, reason: `hides ${JSON.stringify(valueAt(r, c))} in ${excelAddress(r, c)}`,
          hint: "the name uses only the first cell's value" });
      }
    }
  }
  return { depth, columns: parts.map((labels) => labels.join(" ")), parts, problems };
}

What the four parts do, and why:

  1. Counting rows. The header starts as one row. Each group label in it pulls in the row under it, because a group needs names under it. If that row holds a group label too (a year over quarters), the next row comes in as well. The loop stops when nothing grows. We cap the header at maxRows (3) rows, enough for year, quarter and measure, so that a stray merge cannot swallow data rows into the header.
  2. Names. For each column, the code takes what Excel shows in each header row, from top to bottom, and joins the labels with a space. parts keeps the pieces (["Q1", "Revenue"]): use them as the key if you build nested fields, because a joined name can clash with a one-row name such as Q1 Revenue (the duplicate check in step 2 reports that). A number used as a label, such as the year 2026, becomes text.
  3. Checks. Some headers would give wrong names, so they are refused before any record is read: a merge over every named column (read as a title), a group label with no name under one of its columns, a value under a plain label in a lower header row, and a header with no data rows under it. Each problem has a range, a short reason and a hint for the user, and refuse: true.
  4. Hidden values. A value stored in a cell that a merge covers, such as an old name in D1 under "Q1", is not shown by Excel and is not used in any name. It is reported, as for merges in the data, but the file is still read.

The third check needs a word on why. In a lower header row, a value may sit under a group label, or under empty cells (a name aligned to the bottom row, like "Region" in A2 with A1 empty). A value under a plain label, such as "Ana" under "Name", means the row is really data, and the merge that pulled it into the header is a title or just layout. The code checks every cell of the row, so the user sees all of them at once.

The same check refuses a label over a single column with a name under it, such as "Total" over "Amount" next to a merged group. We chose to refuse it: from the cells alone, "Total" over "Amount" has the same shape as "Name" over "Ana", and reading a data row as names would be worse than asking the user to type "Total Amount" in one cell.

Step 2: read the table

readGroupedTable reads the header, then handles the data the same way as the one-row version: fillMerges copies merged group labels such as "North" down and reports merges it should not guess about, and each data row becomes a record with the row number the user sees in Excel.

// Reads an .xlsx file whose header may have up to maxRows rows into records.
// headerTop: index of the first header row. 0 is the first row SheetJS reads
// (Excel row 1 for most files), 1 the row under it.
function readGroupedTable(bytes, headerTop = 0, maxRows = 3) {
  const { rows, merges, origin } = readXlsx(bytes);
  const header = readHeader(rows, merges, headerTop, origin, maxRows);
  if (header.problems.some((p) => p.refuse)) return { columns: [], records: [], notes: [], problems: header.problems };
  const { columns, depth } = header;
  const width = columns.length;
  // The header cells of column c, such as "D1:D2", for messages.
  const headerCells = (c) => XLSX.utils.encode_range({
    s: { r: origin.r + headerTop, c: origin.c + c }, e: { r: origin.r + headerTop + depth - 1, c: origin.c + c } });

  // Merges in the data: the same rules as for a one-row header.
  const firstData = headerTop + depth;
  const filled = fillMerges(rows, merges, firstData, width, origin);
  const problems = [...header.problems, ...filled.problems];
  const isData = (r) => r >= firstData && !filled.skipRows.has(r) &&
    !rows[r].slice(0, width).every(isEmpty);
  const seen = new Set();
  columns.forEach((name, c) => {
    if (name === "") {
      if (rows.some((row, r) => isData(r) && !isEmpty(row[c]))) {
        problems.push({ range: headerCells(c), reason: "has data but no column name" });
      }
      return;
    }
    // Typed twice ("Q1" over two groups): the later column would overwrite the first.
    if (seen.has(name.toLowerCase())) {
      problems.push({ range: headerCells(c), reason: `repeats the column name ${JSON.stringify(name)}` });
    }
    seen.add(name.toLowerCase());
  });

  const records = [];
  rows.forEach((row, r) => {
    if (!isData(r)) return;
    const values = Object.fromEntries(
      columns.flatMap((name, c) => (name ? [[name, row[c] ?? ""]] : [])));
    records.push({ row: origin.r + r + 1, values });
  });
  return { columns: columns.filter((name) => name !== ""), records, notes: filled.notes, problems };
}

headerTop is a row index, not an Excel row number: 0 is the first row SheetJS reads (row 1 for most files), 1 the row under it. Merges that start in the header and run into the data, such as "Region" over A1:A3 in a two-row header, are reported by fillMerges. With a one-row header and no group labels, the result is the same as readMergedTable from the previous post (a test checks this).

Here it is on the sales report, with a try/catch that turns a file that is not .xlsx into a problem too:

let table;
try {
  table = readGroupedTable(await file.arrayBuffer());
} catch (error) {
  // readXlsx throws a TypeError for a file that is not .xlsx, and SheetJS throws for a damaged one.
  console.error(error);
  table = { columns: [], records: [], notes: [], problems: [{ range: null, reason: "the file could not be read as .xlsx" }] };
}
const { columns, records, notes, problems } = table;

columns;
// [ 'Region', 'Rep', 'Q1 Revenue', 'Q1 Cost', 'Q2 Revenue', 'Q2 Cost' ]
records[1];
// { row: 4, values: { Region: 'North', Rep: 'Bo', 'Q1 Revenue': 90, 'Q1 Cost': 50, 'Q2 Revenue': 80, 'Q2 Cost': 40 } }
notes.map((n) => `${n.range}: ${n.reason}`); // [ 'A3:A4: "North" copied into A4' ]
problems; // []

Each Revenue column now says which quarter it belongs to, so your mapping screen can offer Q1 Revenue as its own field.

Headers it refuses

// title, hole and layout hold the bytes of three small .xlsx files
// that this code refuses, with no records:
// title: "Sales 2026" merged across A1:C1, above the column names in row 2.
// hole: "Q1" across B1:C1, with "Revenue" in B2 and nothing in C2.
// layout: "Note" merged across B1:C1 only to make room; row 2 is Ana's data.
const reasons = (table) => table.problems.map((p) => `${p.range}: ${p.reason}`);

reasons(readGroupedTable(title));
// [ 'A1:C1: "Sales 2026" spans the whole table, so it looks like a title' ]
readGroupedTable(title).problems[0].hint; // 'pass the row index of the column names as headerTop'
readGroupedTable(title, 1).columns; // [ 'Name', 'Rep', 'City' ]
reasons(readGroupedTable(hole));
// [ 'B1:C1: "Q1" has no column name under it in C2' ]
reasons(readGroupedTable(layout));
// [ 'A2: "Ana" is under the label "Name" (A1), so row 2 looks like data' ]
readGroupedTable(layout).problems[0].hint;
// 'B1:C1 made row 2 part of the header. If it is a title, pass the row index of the column names as headerTop; if it is layout, unmerge it; if both cells are one name, type the whole name in one cell'

Three more problems come back with the records, without refuse: a value hidden under a header merge, a name used twice ignoring case (the same group label typed over two groups gives two "Q1 Revenue" columns), and a column with data but no name. The last two point at the column's header cells, such as D1:D2.

What this does not cover

  • Group labels typed once without a merge. If "Q1" is in C1 and D1 is just empty, there is no merge to read, so the header is one row. Filling "Q1" to the right would be a guess; ask the user to merge or repeat the label.
  • Labels centered with "Center Across Selection". This Excel alignment centers a label over several cells without merging them (UW-Madison KnowledgeBase, updated 2026-09-01); the file stores it as the centerContinuous alignment (Microsoft's MS-EXSPXML spec, last updated 2020-10-13). There is no merge to read, so the header is one row: on the sales report, the code returns the columns Region, Rep, Q1 and Q2, and reports D1 as a column with data but no name. Ask the user to merge the labels or type full names.
  • A layout merge over text data in every column it covers. If an Id column is merged down and "Contact" is merged over two text columns for looks, the first data row is read as names ("Contact Ana"). Show the column names in your preview so the user can catch it.
  • A real group over every column. "Contact" over First, Last and Email in a three-column table is refused as a title. Passing headerTop 1 reads the names without "Contact".
  • A title over only some columns. "Sales 2026" merged over A1:C1 above four names is read as a group label, so the names start with it ("Sales 2026 Name"), with no problem reported. If you know where the names are, pass headerTop; either way, show the column names in your preview.
  • Data right of the last named column is not read, and no problem is reported, as in the previous post.
  • Group labels stored as dates. A month label such as "Jan 2026" is stored as a number with a date format, so it arrives as 46023 and the names become 46023 Revenue. Convert it as in our post on reading Excel dates, or ask the user to type the label as text.
  • Notes beside the table. A note merged across two cells to the right of the header row is taken for a group label, so the file is refused with problems that point at the note. Ask the user to delete it.
  • CSV and .xls files, other sheets and hidden rows, as in the previous post.
