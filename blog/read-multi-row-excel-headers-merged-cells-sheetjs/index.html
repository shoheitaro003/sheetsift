Read multi-row Excel headers with merged cells in SheetJS

2026-11-27

A customer uploads a sales report whose header has two rows: "Q1" is merged across two columns, with "Revenue" and "Cost" under it. SheetJS reads only the first row as column names, so you get keys like __EMPTY, and the second header row arrives as a record.

By the end of this post you will have readGroupedTable(bytes), about 190 lines that need only SheetJS. It works out how many rows the header has from its merged cells, names each column from top to bottom (Q1 Revenue, Q1 Cost), and refuses headers it cannot name safely, with the Excel address of the cell to fix. Every result quoted below is checked by our test file (the tests named mh:) in Node 22 with SheetJS 0.20.3.

The problem

Here is the file. Each merged range is drawn as one cell:

ABCDEF
1Region
(A1:A2)		Rep
(B1:B2)		Q1 (C1:D1)Q2 (E1:F1)
2RevenueCostRevenueCost
3North
(A3:A4)		Ana1006012070
4Bo90508040
5SouthCy70307535

Read it the usual way, then starting at row 2 with the range option:

// Sales.xlsx: "Region" and "Rep" are merged down over A1:A2 and B1:B2,
// "Q1" across C1:D1 and "Q2" across E1:F1, with Revenue and Cost under each.
// bytes: the file's contents, e.g. new Uint8Array(await file.arrayBuffer()).
const workbook = XLSX.read(bytes);
const sheet = workbook.Sheets[workbook.SheetNames[0]];
const records = XLSX.utils.sheet_to_json(sheet);
records.length;                    // 4  (row 2, the second header row, is read as a record)
Object.keys(records[0]).join(", ");  // 'Q1, __EMPTY, Q2, __EMPTY_1'
const fromRow2 = XLSX.utils.sheet_to_json(sheet, { range: 1 });
Object.keys(fromRow2[0]).join(", "); // '__EMPTY, __EMPTY_1, Revenue, Cost, Revenue_1, Cost_1'

Excel keeps a merged range's value in its top-left cell (SheetJS docs on merged cells, updated 2026-08-03), so D1 and F1 are empty and SheetJS invents __EMPTY names for them. (Region and Rep are missing from the first record because A2 and B2 are empty, and sheet_to_json leaves empty cells out.) Starting at row 2 loses "Q1" and "Q2" instead: the two Revenue columns become Revenue and Revenue_1, and nothing says which quarter is which.

If you control the template

When every file has the same two header rows, skip them and pass your own names:

// Only for a template you control: the header is always rows 1-2 of Sales.xlsx.
const columns = ["Region", "Rep", "Q1 Revenue", "Q1 Cost", "Q2 Revenue", "Q2 Cost"];
const records = XLSX.utils.sheet_to_json(sheet, { header: columns, range: 2 });
records[1]; // { Rep: 'Bo', 'Q1 Revenue': 90, 'Q1 Cost': 50, 'Q2 Revenue': 80, 'Q2 Cost': 40 }

This breaks as soon as a user adds a column. (Bo's record has no Region because "North" is stored in A3 only; more on that below.) For files from users, read the header from the merges.

How the code decides where the header ends

SheetJS lists the merged ranges of a sheet in its !merges array. The code calls a merge with text across two or more columns, like "Q1" over C1:D1, a group label. The columns under a group label need their own names, so the row under it belongs to the header too. If that row holds another group label (a year over quarters), the header grows again, up to a limit of three rows.

Any other text in the header is a plain label: "Region", even though it is merged down over A1:A2, names one column. An empty merge is layout and is ignored.

Step 1: read the sheet

readSheet returns every row as an array (defval: null keeps empty cells, blankrows: true keeps empty rows, so row indexes match the sheet) and turns each merge into row and column indexes. A sheet's stored range (its !ref) does not always start at A1, so both count from the start of that range, origin, and messages convert back to Excel addresses. The two helpers at the end are shared by the next steps.

// npm install https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz
import * as XLSX from "xlsx";

const hasText = (value) => String(value ?? "").trim() !== "";
// Line breaks typed with Alt+Enter and runs of spaces become one space.
const tidy = (value) => String(value).replace(/\s+/g, " ").trim();

// Reads the first sheet. rows: one array of cells per row. merges: the merged
// ranges. Both count from 0 at the start of the sheet's range (its "!ref").
function readSheet(bytes) {
  const workbook = XLSX.read(bytes);
  const sheet = workbook.Sheets[workbook.SheetNames[0]];
  if (!sheet?.["!ref"]) return { rows: [], merges: [], origin: { r: 0, c: 0 } };
  const origin = XLSX.utils.decode_range(sheet["!ref"]).s;
  const rows = XLSX.utils.sheet_to_json(sheet, {
    header: 1, defval: null, blankrows: true, raw: true });
  const merges = (sheet["!merges"] ?? []).map((m) => ({
    address: XLSX.utils.encode_range(m), // "C1:D1", for messages
    top: m.s.r - origin.r, bottom: m.e.r - origin.r,
    left: m.s.c - origin.c, right: m.e.c - origin.c,
  }));
  return { rows, merges, origin };
}

// The text of a merge (in its top-left cell). A merge can lie outside the
// sheet's range, so the row may not exist.
const mergeText = (rows, m) => rows[m.top]?.[m.left];
// A group label: a merge with text across two or more columns.
const isGroupLabel = (rows, m) => m.right > m.left && hasText(mergeText(rows, m));

The install line points at cdn.sheetjs.com, which SheetJS calls its primary software distribution site (SheetJS installation docs, updated 2026-08-03); 0.20.3 is the version our tests run. XLSX.read accepts the Uint8Array you get from a File.

Step 2: find the header rows

findHeaderRows grows the header from its first row until every group label has a row of names under it. Then it refuses shapes that would give wrong names for every column, in this order:

  • Title. A group label in the first row over every named column ("Sales 2026" over A1:C1) would start every name. The hint gives the Excel row of the first non-empty row under it, to pass as headerRow.
  • Too tall: more than maxRows rows (default 3), or a header that runs past the end of the sheet. The title check comes first, so a title over a tall header still gets the title hint.
  • A merge across the edge of the header. "Region" merged over A1:A3 in a two-row header would leave row 3's region empty.

It also refuses an empty first row and a headerRow outside the sheet.

// Finds the header rows. headerRow is the Excel row number of its first row.
// Returns { top, end } (row indexes; end is the first row after the header)
// or { problem }.
function findHeaderRows(sheet, { headerRow = sheet.origin.r + 1, maxRows = 3 } = {}) {
  const { rows, merges, origin } = sheet;
  const top = headerRow - 1 - origin.r;
  const label = (m) => `"${tidy(mergeText(rows, m))}" (${m.address})`;
  const problem = (range, reason, hint) => ({ problem: { range, reason, hint } });
  if (top < 0 || top >= rows.length) return problem(null, `row ${headerRow} is outside the sheet`);
  if (!rows[top].some(hasText)) return problem(null, `row ${headerRow} is empty`,
    "pass headerRow: the Excel row number of the column names");

  // Each group label needs a row of names under it: grow the header until
  // every group label that starts in it has one.
  let end = top + 1;
  for (;;) {
    const groups = merges.filter((m) => isGroupLabel(rows, m) && m.top >= top && m.top < end);
    const needed = Math.max(end, ...groups.map((m) => m.bottom + 2));
    if (needed === end) break;
    end = needed;
  }
  const lastRow = headerRow + (end - top) - 1;
  if (end > rows.length) return problem(null,
    `the header (rows ${headerRow}-${lastRow}) runs past the end of the sheet`);

  // A title: a group label in the first row over every column that has a label.
  const labelled = (c) => {
    for (let r = top; r < end; r++) {
      if (hasText(rows[r]?.[c])) return true;
    }
    return merges.some((m) => hasText(mergeText(rows, m)) && m.left <= c && c <= m.right &&
      m.top < end && m.bottom >= top);
  };
  const width = Math.max(...rows.slice(top, end).map((row) => row.length));
  const named = [];
  for (let c = 0; c < width; c++) if (labelled(c)) named.push(c);
  const title = merges.find((m) => isGroupLabel(rows, m) && m.top === top &&
    named.length > 1 && m.left <= named[0] && m.right >= named.at(-1));
  if (title) {
    const next = rows.findIndex((row, r) => r > title.bottom && row.some(hasText));
    return problem(title.address, `${label(title)} spans every column, so it looks like a title`,
      next < 0 ? undefined : `pass headerRow: ${next + origin.r + 1} if the names start there`);
  }
  if (end - top > maxRows) return problem(null,
    `the merges make a header of ${end - top} rows; the limit is ${maxRows}`,
    "check the merges, or pass a larger maxRows if the header is real");

  // A labelled merge that starts above the header or reaches below it.
  const crossing = merges.find((m) => hasText(mergeText(rows, m)) &&
    m.bottom >= top && m.top < end &&       // it touches the header
    (m.top < top || m.bottom >= end));      // and goes past its edge
  if (crossing) return problem(crossing.address,
    `${label(crossing)} crosses the edge of the header (rows ${headerRow}-${lastRow})`,
    `merge it over rows ${headerRow}-${lastRow} only, or unmerge it`);
  return { top, end, headerRow, lastRow };
}

Step 3: name the columns

readHeader walks each column from top to bottom and joins the labels it sees with a space. A merge counts once however many rows it covers, and line breaks inside a cell become spaces. Then it checks the cells:

  • Text under a plain label. If a merge made for layout ("Note" over B1:C1) turns a one-row header into two rows, the first data row is read as names. Its tell: "Ana" sits under "Name", which is not a group label. Every such cell is reported.
  • Hole. A column under a group label with no name below it would be called just "Q1".
  • Same name twice. The second column would overwrite the first in every record. Names that differ only in case are refused too, because a column mapping that ignores case would mix them up.
  • No data under the header.
// Names each column from the header rows, top to bottom: "Q1" over "Revenue"
// gives "Q1 Revenue". Returns { columns, end } or { problems }.
function readHeader(sheet, options) {
  const { rows, merges, origin } = sheet;
  const found = findHeaderRows(sheet, options);
  if (found.problem) return { problems: [found.problem] };
  const { top, end } = found;
  const cellAt = (r, c) => XLSX.utils.encode_cell({ r: r + origin.r, c: c + origin.c });
  const mergeAt = (r, c) =>
    merges.find((m) => r >= m.top && r <= m.bottom && c >= m.left && c <= m.right);
  // What Excel shows: a merge shows the value of its top-left cell.
  const shown = (r, c) => {
    const m = mergeAt(r, c);
    return m ? mergeText(rows, m) : rows[r][c];
  };
  const headerRows = [];
  for (let r = top; r < end; r++) headerRows.push(r);
  const groups = merges.filter((m) => isGroupLabel(rows, m) && m.top >= top && m.top < end);
  const width = Math.max(...headerRows.map((r) => rows[r].length));

  const columns = [], problems = [];
  for (let c = 0; c < width; c++) {
    const parts = [];
    let lastMerge = null;  // a merge counts once, however many rows it covers
    let plainLabel = null; // the last label above that is not a group label
    for (const r of headerRows) {
      const m = mergeAt(r, c);
      if (m && m === lastMerge) continue;
      lastMerge = m;
      const value = shown(r, c);
      if (!hasText(value)) continue;
      // Text under a plain label is a data row that a merge pulled into the header.
      if (plainLabel !== null) problems.push({ range: cellAt(r, c),
        reason: `"${tidy(value)}" is under "${tidy(plainLabel)}", ` +
          `which is not a group label, so row ${r + origin.r + 1} looks like data`,
        hint: "unmerge cells that are only layout, or type the full name in one cell" });
      if (!groups.includes(m)) plainLabel = value;
      parts.push(tidy(value));
    }
    // Every column under a group label needs a name in a row below the label.
    for (const g of groups) {
      if (c < g.left || c > g.right) continue;
      if (headerRows.some((r) => r > g.bottom && hasText(shown(r, c)))) continue;
      problems.push({ range: cellAt(g.bottom + 1, c),
        reason: `"${tidy(mergeText(rows, g))}" (${g.address}) has no column name under it here`,
        hint: "type the column's name in this cell" });
    }
    if (parts.length) columns.push({ name: parts.join(" "), parts, index: c,
      letter: XLSX.utils.encode_col(c + origin.c) });
  }
  if (problems.length) return { problems };
  if (!rows.slice(end).some((row) => row.some(hasText))) return { problems: [{ range: null,
    reason: `there are no data rows under the header (rows ${found.headerRow}-${found.lastRow})` }] };

  // A repeated name would overwrite the first column's value in every record.
  // Names that differ only in case are refused too: a mapping that ignores
  // case would mix them up.
  const seen = new Map();
  for (const col of columns) {
    const first = seen.get(col.name.toLowerCase());
    if (!first) { seen.set(col.name.toLowerCase(), col); continue; }
    problems.push({ range: col.letter,
      reason: `column ${col.letter} has the same name as column ${first.letter}: "${first.name}"`,
      hint: "rename one of them" });
  }
  return problems.length ? { problems } : { columns, end };
}

Each column also keeps parts (["Q1", "Revenue"]), if you would rather build nested fields than join the labels.

Step 4: read the records

readGroupedTable turns each row under the header into a record with the row number the user sees in Excel, so your error messages can point at it. It skips blank rows.

// Reads the records under the header. Each record has its Excel row number.
function readGroupedTable(bytes, options) {
  const sheet = readSheet(bytes);
  const header = readHeader(sheet, options);
  const { rows, merges, origin } = sheet;
  if (header.problems) {
    return { columns: [], records: [], notes: [], problems: header.problems };
  }
  const records = [], notes = [];
  for (let r = header.end; r < rows.length; r++) {
    if (!rows[r].some(hasText)) continue; // blank row
    // fromEntries keeps a column named "__proto__" as an ordinary key.
    const values = Object.fromEntries(
      header.columns.map((col) => [col.name, rows[r][col.index] ?? null]));
    records.push({ row: r + origin.r + 1, values });
  }
  // A loop, not Math.max(...rows): spreading 100,000 rows overflows the stack.
  let width = 0;
  for (const row of rows) width = Math.max(width, row.length);
  const data = rows.slice(header.end);
  for (let c = 0; c < width; c++) {
    const named = header.columns.some((col) => col.index === c);
    if (!named && data.some((row) => hasText(row[c]))) notes.push({
      range: XLSX.utils.encode_col(c + origin.c),
      reason: "this column has data but no name, so it was left out" });
  }
  for (const m of merges) {
    const first = XLSX.utils.encode_cell({ r: m.top + origin.r, c: m.left + origin.c });
    if (m.top >= header.end) notes.push({ range: m.address,
      reason: `merged in the data: only ${first} holds the value` });
  }
  const columns = header.columns.map((col) => col.name);
  return { columns, records, notes, problems: [] };
}

It does not fill merged cells in the data. "North" over A3:A4 is stored in A3 only, so Bo's Region is null; the function returns a note for each such merge instead of guessing. Our post on filling merged cells covers when copying the value down is safe.

Values come back as stored (raw: true), so dates in the data arrive as serial numbers; our post on reading Excel dates converts them. A sheet with many merges in the data gives one note per merge, so group them by column before you show them.

Here it is on the sales report:

// file: a File from <input type="file">, inside an async change handler.
const bytes = new Uint8Array(await file.arrayBuffer());
const { columns, records, notes, problems } = readGroupedTable(bytes);
columns;
// [ 'Region', 'Rep', 'Q1 Revenue', 'Q1 Cost', 'Q2 Revenue', 'Q2 Cost' ]
records[0];
// { row: 3, values: { Region: 'North', Rep: 'Ana', 'Q1 Revenue': 100, 'Q1 Cost': 60, 'Q2 Revenue': 120, 'Q2 Cost': 70 } }
records[1].values.Region; // null
notes.map((n) => `${n.range}: ${n.reason}`);
// [ 'A3:A4: merged in the data: only A3 holds the value' ]
problems; // []

Each Revenue column now says which quarter it belongs to, so your column mapping can treat Q1 Revenue as its own field. A non-empty problems means nothing was imported; show each reason next to its cell and the hint under it. Notes are warnings: the records came back, but show them before you save.

Headers it refuses

// title, hole, layout and total hold the bytes of four small .xlsx files:
// title: "Sales 2026" merged across A1:C1, above the names Name, Rep, City in row 2.
// hole: "Name" merged over A1:A2; "Q1" merged across B1:C1, with "Revenue"
//   in B2 and nothing in C2.
// layout: "Name" in A1 and "Note" merged across B1:C1 only to make room;
//   row 2 is Ana's data: Ana, hi, 5.
// total: "Q1" merged across A1:B1 over Revenue and Cost; "Total" in C1 over
//   "Amount" in C2, not merged.
const reasons = (table) => table.problems.map((p) => `${p.range}: ${p.reason}`);
const titled = readGroupedTable(title);
reasons(titled);
// [ 'A1:C1: "Sales 2026" (A1:C1) spans every column, so it looks like a title' ]
titled.problems[0].hint; // 'pass headerRow: 2 if the names start there'
readGroupedTable(title, { headerRow: 2 }).columns; // [ 'Name', 'Rep', 'City' ]
reasons(readGroupedTable(hole));
// [ 'C2: "Q1" (B1:C1) has no column name under it here' ]
reasons(readGroupedTable(layout));
// [ 'A2: "Ana" is under "Name", which is not a group label, so row 2 looks like data' ]
reasons(readGroupedTable(total));
// [ 'C2: "Amount" is under "Total", which is not a group label, so row 2 looks like data' ]

The "Total" over "Amount" refusal is a choice. From the cells alone it looks exactly like "Name" over "Ana", and reading a data row as column names is worse than asking the user to type one name.

What this does not cover

  • Labels that look merged but are not. Excel's Center Across Selection centers a label over several cells without merging them (UW-Madison KnowledgeBase, updated 2026-09-01). A label typed once over two columns with no merge is the same. There is no merge to read, so the header is one row: the sales report comes back with columns Region, Rep, Q1 and Q2, its first record is the Revenue row, and columns D and F get a "data but no name" note. Ask the user to merge the labels or type full names.
  • A group label over every column ("Contact" over First, Last and Email, with nothing beside it) looks exactly like a title, so it is refused. Importing with the suggested headerRow reads the names without "Contact".
  • A title over only some columns ("Sales 2026" over three of four names) is read as a group label: the names become "Sales 2026 Name". Pass headerRow if you know where the names start.
  • A layout merge over text data in every column under it, next to a column merged down, reads the first data row as names ("Contact Ana"). Show the column names in your import preview so the user can catch it.
  • A note merged beside the header is taken for a group label, and the file is refused with problems in that row.
  • Group labels stored as dates, such as "Jan 2026", arrive as serial numbers (46023 Revenue). Convert them as in our post on reading Excel dates.
  • Values hidden under a merge. An .xlsx file can store values in the covered cells of a merge (same SheetJS page). The code uses only what Excel shows, the top-left value, and ignores the rest.
  • Other sheets, hidden rows, and finding where the header starts. The code reads the first sheet and starts at its first row unless you pass headerRow; our post on finding the header row can supply it. CSV files have no merges, so they read as one-row headers.
