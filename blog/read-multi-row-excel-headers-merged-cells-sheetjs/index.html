Read multi-row Excel headers with merged cells in SheetJS

2026-11-25

A customer uploads a sales report whose header has two rows: "Q1" is merged across two columns, with "Revenue" and "Cost" under it. SheetJS reads the first row as the column names, so you get keys like __EMPTY, and the second header row arrives as a record.

By the end of this post you will have readGroupedTable(bytes): it finds how many rows the header has from its merged cells, names each column from top to bottom (Q1 Revenue, Q1 Cost), and refuses headers it cannot name with confidence, with the Excel address of the cell to fix. The code is not self-contained: it adds two functions to the module from our post on filling merged cells and uses its readXlsx, fillMerges, isEmpty and isLabel, which also handle merges in the data rows. Every result quoted below is checked by our test file (the tests named mh:) in Node 22 with SheetJS 0.20.3.

The problem

Here is the file. Each merged range is drawn as one cell:

ABCDEF
1Region
(A1:A2)		Rep
(B1:B2)		Q1 (C1:D1)Q2 (E1:F1)
2RevenueCostRevenueCost
3North
(A3:A4)		Ana1006012070
4Bo90508040
5SouthCy70307535

Read the usual way, and then starting at row 2 with the range option:

// Sales.xlsx: "Region" and "Rep" are merged down over A1:A2 and B1:B2,
// "Q1" across C1:D1 and "Q2" across E1:F1, with Revenue and Cost under each.
const sheet = workbook.Sheets[workbook.SheetNames[0]];
const records = XLSX.utils.sheet_to_json(sheet);
records.length;                    // 4  (row 2, the second header row, is read as a record)
Object.keys(records[0]).join(", ");  // 'Q1, __EMPTY, Q2, __EMPTY_1'
const fromRow2 = XLSX.utils.sheet_to_json(sheet, { range: 1 });
Object.keys(fromRow2[0]).join(", "); // '__EMPTY, __EMPTY_1, Revenue, Cost, Revenue_1, Cost_1'

A merged range stores its value in its first (top-left) cell only, so D1 and F1 are empty and SheetJS invents __EMPTY names for them. Starting at row 2 loses "Q1" and "Q2" instead, and the two Revenue columns become Revenue and Revenue_1. Neither tells your column mapping which quarter a number belongs to.

Step 1: read the header

The merges tell you the shape of the header. A label merged across columns is a group label: it says that the columns under it share a name, so the row under it must be part of the header too. A label merged down, like "Region" over A1:A2, just fills the header's height and counts once in the name. A merge with no value is layout, and is ignored.

Add this function to the module from the previous post.

// Reads a header that starts at row `top` and may have up to maxRows rows.
// A cell merged across columns ("Q1" over C1:D1) is a group label, so the row
// below it is part of the header too. Returns one name per column ("Q1 Revenue"),
// the parts of each name (["Q1", "Revenue"]) and the number of header rows.
function readHeader(rows, merges, top, origin, maxRows = 3) {
  const excelAddress = (r, c) => XLSX.utils.encode_cell({ r: origin.r + r, c: origin.c + c });
  const valueAt = (r, c) => rows[r]?.[c] ?? "";
  const mergeAt = (r, c) => merges.find((m) => m.top <= r && r <= m.bottom && m.left <= c && c <= m.right);
  // What Excel shows in a cell: the first cell's value for any cell of a merge.
  const shown = (r, c) => { const m = mergeAt(r, c); return m ? valueAt(m.top, m.left) : valueAt(r, c); };
  const fail = (range, reason) => ({ depth: 0, columns: [], parts: [], problems: [{ range, reason }] });

  // 1. Count the header rows. Each group label needs one row of names under it,
  //    and a group in that row (a year over quarters) needs another row.
  //    Empty merges are layout, not labels, and are ignored.
  const isGroup = (m) => m.right > m.left && !isEmpty(valueAt(m.top, m.left));
  let depth = 1;
  for (let grown = true; grown; ) {
    grown = false;
    for (const m of merges) {
      if (!isGroup(m) || m.top < top || m.top >= top + depth) continue;
      if (m.bottom - top + 2 > depth) { depth = m.bottom - top + 2; grown = true; }
    }
  }
  if (depth > maxRows) return fail(excelAddress(top, 0), `the header would have ${depth} rows; this code reads at most ${maxRows}`);
  if (top + depth > rows.length) return fail(excelAddress(top, 0), "the header has no data rows under it");

  // 2. One name per column: the labels from top to bottom, joined with a space.
  //    A label merged down ("Region" over A1:A2) counts once.
  const parts = [];
  const lastColumn = Math.max(0, ...rows.slice(top, top + depth).map((row) => row.length));
  for (let c = 0; c < lastColumn; c++) {
    const labels = [];
    let previous;
    for (let r = top; r < top + depth; r++) {
      const m = mergeAt(r, c);
      if (m && m === previous) continue;
      previous = m;
      const value = shown(r, c);
      if (!isEmpty(value)) labels.push(String(value).trim());
    }
    parts.push(labels);
  }
  const first = parts.findIndex((labels) => labels.length > 0); // first named column
  const width = parts.findLastIndex((labels) => labels.length > 0) + 1;
  if (width === 0) return fail(excelAddress(top, 0), "the header row has no column names; if the header is lower, pass its index as headerTop");
  parts.length = width;

  // 3. Refuse what would give wrong names, before any record is read.
  const problems = [];
  for (const m of merges) {
    if (!isGroup(m) || m.top < top || m.top >= top + depth || m.left >= width) continue;
    if (m.left <= first && m.right >= width - 1 && width - first > 1) {
      // A cell over every named column is read as a title: it would start every name.
      problems.push({ range: m.address, reason: "spans the whole table, so it looks like a title; pass the row of the column names as headerTop" });
      continue;
    }
    // Every column under a group label needs a name in some header row below it.
    for (let c = m.left; c <= Math.min(m.right, width - 1); c++) {
      let named = false;
      for (let r = m.bottom + 1; r < top + depth; r++) named ||= !isEmpty(shown(r, c));
      if (!named) {
        problems.push({ range: m.address, reason: `${JSON.stringify(valueAt(m.top, m.left))} has no column name under it in ${excelAddress(m.bottom + 1, c)}` });
      }
    }
  }
  // Under the first header row, a value must be part of a merge, sit under a group
  // label, or have only empty cells above it (a name aligned to the bottom row).
  // A value under a plain label, such as "Ana" under "Name", means the merge that
  // made this row part of the header is not a group label: it is a title or layout.
  const labelAbove = (r, c) => {
    for (let a = r - 1; a >= top; a--) if (!isEmpty(shown(a, c))) return a;
    return -1;
  };
  for (let r = top + 1; r < top + depth; r++) {
    const c = [...Array(width).keys()].find((c) => {
      const a = labelAbove(r, c);
      return !isEmpty(valueAt(r, c)) && !mergeAt(r, c) && a >= 0 && !isGroup(mergeAt(a, c) ?? {});
    });
    if (c === undefined) continue;
    // A group label in the header made row r a header row, so one is always found.
    const cause = merges.find((g) => isGroup(g) && g.top >= top && g.top < r &&
      g.bottom + 1 >= r && g.left < width);
    const a = labelAbove(r, c);
    const value = JSON.stringify(valueAt(r, c));
    const label = JSON.stringify(shown(a, c));
    problems.push({ range: excelAddress(r, c), reason: `${value} is under ${label} (${excelAddress(a, c)}), not under a group label, yet ${cause.address} makes row ${origin.r + r + 1} a header row. ` +
      `If ${cause.address} is a title, pass the row of the column names as headerTop; if it is layout, unmerge it; if ${value} is part of a name, type the whole name in one cell` });
  }
  if (problems.length > 0) return { depth: 0, columns: [], parts: [], problems };
  return { depth, columns: parts.map((labels) => labels.join(" ")), parts, problems };
}

What the three parts do, and why:

  • Counting rows. The header starts as one row. Each group label in it pulls in the row under it. If that row holds a group label too (a year over quarters), the next row comes in as well. The loop stops when nothing grows. We cap the header at maxRows (3) rows, enough for year, quarter and measure, so that a stray merge in the data cannot swallow data rows into the header.
  • Names. For each column, the code takes what Excel shows in each header row, from top to bottom, and joins the labels with a space. parts keeps the pieces (["Q1", "Revenue"]): use them as the key if you build nested fields, because a joined name can clash with a one-row name such as Q1 Revenue (the duplicate check below reports that). A number used as a label, such as the year 2026, becomes text.
  • Checks. Three kinds of header would give wrong names, so they are refused before any record is read (examples in the next sections). A merge over every named column is read as a title. A column under a group label must have a name in a lower header row. And in a lower header row, a value may sit under a group label or under empty cells (a name aligned to the bottom row, like "Region" in A2 with A1 empty), but not under a plain label: "Ana" under "Name" means the merge that made this row part of the header is layout or a title, and the row is really data.

Step 2: read the table

readGroupedTable reads the header, then handles the data the same way as the one-row version: fillMerges copies merged group labels such as "North" down and reports merges it should not guess about, and each data row becomes a record with the row number the user sees in Excel.

// Reads an .xlsx file whose header may have up to maxRows rows into records.
// headerTop: index of the first header row, counted from the first row of the
// stored range (0 for most files).
function readGroupedTable(bytes, headerTop = 0, maxRows = 3) {
  const { rows, merges, origin } = readXlsx(bytes);
  const header = readHeader(rows, merges, headerTop, origin, maxRows);
  if (header.problems.length > 0) return { columns: [], records: [], notes: [], problems: header.problems };
  const { columns, depth } = header;
  const width = columns.length;
  // The header cells of column c, such as "D1:D2", for messages.
  const headerCells = (c) => XLSX.utils.encode_range({
    s: { r: origin.r + headerTop, c: origin.c + c }, e: { r: origin.r + headerTop + depth - 1, c: origin.c + c } });

  // Merges in the data: the same rules as for a one-row header.
  const firstData = headerTop + depth;
  const filled = fillMerges(rows, merges, firstData, width, origin);
  const problems = [...filled.problems];
  const isData = (r) => r >= firstData && !filled.skipRows.has(r) &&
    !rows[r].slice(0, width).every(isEmpty);
  const seen = new Set();
  columns.forEach((name, c) => {
    if (name === "") {
      if (rows.some((row, r) => isData(r) && !isEmpty(row[c]))) {
        problems.push({ range: headerCells(c), reason: "has data but no column name" });
      }
      return;
    }
    // Typed twice ("Q1" over two groups): the later column would overwrite the first.
    if (seen.has(name.toLowerCase())) {
      problems.push({ range: headerCells(c), reason: `repeats the column name ${JSON.stringify(name)}` });
    }
    seen.add(name.toLowerCase());
  });

  const records = [];
  rows.forEach((row, r) => {
    if (!isData(r)) return;
    const values = Object.fromEntries(
      columns.flatMap((name, c) => (name ? [[name, row[c] ?? ""]] : [])));
    records.push({ row: origin.r + r + 1, values });
  });
  return { columns: columns.filter((name) => name !== ""), records, notes: filled.notes, problems };
}

Merges that start in the header and run into the data, such as "Region" over A1:A3 in a two-row header, are reported by fillMerges. With a one-row header and no group labels, the result is the same as readMergedTable from the previous post (a test checks this).

Here it is on the sales report, with a try/catch that turns a file that is not .xlsx into a problem too:

let table;
try {
  table = readGroupedTable(await file.arrayBuffer());
} catch (error) {
  // readXlsx throws a TypeError for a file that is not .xlsx, and SheetJS throws for a damaged one.
  console.error(error);
  table = { columns: [], records: [], notes: [], problems: [{ range: null, reason: "the file could not be read as .xlsx" }] };
}
const { columns, records, notes, problems } = table;

columns;
// [ 'Region', 'Rep', 'Q1 Revenue', 'Q1 Cost', 'Q2 Revenue', 'Q2 Cost' ]
records[1];
// { row: 4, values: { Region: 'North', Rep: 'Bo', 'Q1 Revenue': 90, 'Q1 Cost': 50, 'Q2 Revenue': 80, 'Q2 Cost': 40 } }
notes.map((n) => `${n.range}: ${n.reason}`); // [ 'A3:A4: "North" copied into A4' ]
problems; // []

Each Revenue column now says which quarter it belongs to, so your mapping screen can offer Q1 Revenue as its own field.

Headers it refuses

// title, hole and layout hold the bytes of three small .xlsx files
// that this code refuses, with no records:
// title: "Sales 2026" merged across A1:C1, above the column names in row 2.
// hole: "Q1" across B1:C1, with "Revenue" in B2 and nothing in C2.
// layout: "Note" merged across B1:C1 only to make room; row 2 is Ana's data.
const reasons = (table) => table.problems.map((p) => `${p.range}: ${p.reason}`);

reasons(readGroupedTable(title));
// [ 'A1:C1: spans the whole table, so it looks like a title; pass the row of the column names as headerTop' ]
readGroupedTable(title, 1).columns; // [ 'Name', 'Rep', 'City' ]
reasons(readGroupedTable(hole));
// [ 'B1:C1: "Q1" has no column name under it in C2' ]
reasons(readGroupedTable(layout));
// [ 'A2: "Ana" is under "Name" (A1), not under a group label, yet B1:C1 makes row 2 a header row. If B1:C1 is a title, pass the row of the column names as headerTop; if it is layout, unmerge it; if "Ana" is part of a name, type the whole name in one cell' ]

HeaderWhy it is refusedWhat to do

A group label with an empty cell under itThat column's name would be just "Q1"Type the missing name, or unmerge the label

Two more problems come back with the records, as in the one-row version: a name used twice, ignoring case (the same group label typed over two groups gives two "Q1 Revenue" columns), and a column with data but no name. Both point at the column's header cells, such as D1:D2.

What this does not cover

  • Group labels typed once without a merge. If "Q1" is in C1 and D1 is just empty, there is no merge to read, so the header is one row. Filling "Q1" to the right would be a guess; ask the user to merge or repeat the label.
  • A layout merge over text data in every column it covers. If an Id column is merged down and "Contact" is merged over two text columns for looks, the first data row is read as names ("Contact Ana"). Show the column names in your preview so the user can catch it.
  • A real group over every column. "Contact" over First, Last and Email in a three-column table is refused as a title. Passing headerTop 1 reads the names without "Contact".
  • A title over only some columns. "Sales 2026" merged over A1:C1 above four names is read as a group label, so the names start with it ("Sales 2026 Name"), with no problem reported. If you know where the names are, pass headerTop; either way, show the column names in your preview.
  • Data right of the last named column is not read, and no problem is reported, as in the previous post.
  • Group labels stored as dates. A month label such as "Jan 2026" is stored as a number with a date format, so it arrives as 46023 and the names become 46023 Revenue. Convert it as in our post on reading Excel dates, or ask the user to type the label as text.
  • Notes beside the table. A note merged across two cells to the right of the header row is taken for a group label, so the file is refused with problems that point at the note. Ask the user to delete it.
  • CSV and .xls files, other sheets and hidden rows, as in the previous post.
