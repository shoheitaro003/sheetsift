Read multi-row Excel headers with merged cells in SheetJS

2026-11-26

A customer uploads a sales report whose header has two rows: "Q1" is merged across two columns, with "Revenue" and "Cost" under it. SheetJS reads the first row as the column names, so you get keys like __EMPTY, and the second header row arrives as a record.

By the end of this post you will have readGroupedTable(bytes): it finds how many rows the header has from its merged cells, names each column from top to bottom (Q1 Revenue, Q1 Cost), and refuses headers it cannot name with confidence, with the Excel address of the cell to fix. If you control the template, a few lines are enough (shown first); the rest of the post is for files from users, whose layout you do not know. Every result quoted below is checked by our test file (the tests named mh:) in Node 22 with SheetJS 0.20.3.

The problem

Here is the file. Each merged range is drawn as one cell:

ABCDEF
1Region
(A1:A2)		Rep
(B1:B2)		Q1 (C1:D1)Q2 (E1:F1)
2RevenueCostRevenueCost
3North
(A3:A4)		Ana1006012070
4Bo90508040
5SouthCy70307535

Read the usual way, and then starting at row 2 with the range option:

// Sales.xlsx: "Region" and "Rep" are merged down over A1:A2 and B1:B2,
// "Q1" across C1:D1 and "Q2" across E1:F1, with Revenue and Cost under each.
const sheet = workbook.Sheets[workbook.SheetNames[0]];
const records = XLSX.utils.sheet_to_json(sheet);
records.length;                    // 4  (row 2, the second header row, is read as a record)
Object.keys(records[0]).join(", ");  // 'Q1, __EMPTY, Q2, __EMPTY_1'
const fromRow2 = XLSX.utils.sheet_to_json(sheet, { range: 1 });
Object.keys(fromRow2[0]).join(", "); // '__EMPTY, __EMPTY_1, Revenue, Cost, Revenue_1, Cost_1'

A merged range stores its value in its first (top-left) cell only, so D1 and F1 are empty and SheetJS invents __EMPTY names for them. (Region and Rep are missing from the first record because A2 and B2 are empty, and sheet_to_json leaves empty cells out.) Starting at row 2 loses "Q1" and "Q2" instead, and the two Revenue columns become Revenue and Revenue_1. Neither tells your column mapping which quarter a number belongs to.

If you control the template

When every file has the same two header rows, skip them and pass your own names:

// Only for a template you control: the header is always rows 1-2 of Sales.xlsx.
const columns = ["Region", "Rep", "Q1 Revenue", "Q1 Cost", "Q2 Revenue", "Q2 Cost"];
const records = XLSX.utils.sheet_to_json(sheet, { header: columns, range: 2 });
records[1]; // { Rep: 'Bo', 'Q1 Revenue': 90, 'Q1 Cost': 50, 'Q2 Revenue': 80, 'Q2 Cost': 40 }

This breaks as soon as a user adds a column or a row, and it does not fill merged data cells: Bo's record has no Region, because "North" sits in A3 only. For files from users, read the header from the merges, as below.

What you need from the previous post

The code builds on our post on filling merged cells. This part turns SheetJS's !merges into row and column indexes that match rows:

// npm install https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz
import * as XLSX from "xlsx";

const isEmpty = (value) => String(value ?? "").trim() === "";
const isLabel = (value) => typeof value === "string" && value.trim() !== "";

// Reads the first sheet of an .xlsx file.
// rows: one array of cells per row. merges: the merged ranges.
// Both count from 0 at the first cell of the sheet's stored range (origin).
function readXlsx(bytes) {
  const data = bytes instanceof ArrayBuffer ? new Uint8Array(bytes) : bytes;
  // An .xlsx file is a zip archive, and zip archives start with the bytes "PK".
  if (data[0] !== 0x50 || data[1] !== 0x4b) throw new TypeError("not an .xlsx file");
  const workbook = XLSX.read(data);
  const sheet = workbook.Sheets[workbook.SheetNames[0]];
  if (!sheet?.["!ref"]) return { rows: [], merges: [], origin: { r: 0, c: 0 } };
  const origin = XLSX.utils.decode_range(sheet["!ref"]).s;
  const rows = XLSX.utils.sheet_to_json(sheet, {
    header: 1, defval: "", blankrows: true, raw: true });
  const merges = (sheet["!merges"] ?? []).map((m) => ({
    address: XLSX.utils.encode_range(m), // "A2:A4", for messages
    top: m.s.r - origin.r, bottom: m.e.r - origin.r,
    left: m.s.c - origin.c, right: m.e.c - origin.c,
  }));
  return { rows, merges, origin };
}

blankrows and defval keep every row an array with a cell for every column, so the code below can index rows directly. On the sales report:

const { rows, merges, origin } = readXlsx(bytes);
rows[0];    // [ 'Region', 'Rep', 'Q1', '', 'Q2', '' ]
merges[2];  // { address: 'E1:F1', top: 0, bottom: 0, left: 4, right: 5 }
origin;     // { c: 0, r: 0 }

Copy fillMerges from the previous post too (about 60 lines): it copies merged labels in the data rows down (like "North") and returns notes and problems for the user, plus skipRows, the indexes of rows that are titles or footnotes. The code also uses Array.prototype.findLastIndex and at, in Node 18+ and current browsers.

Step 1: count the header rows

The merges tell you the shape of the header. A label merged across columns is a group label: the columns under it share it, so the row under it must hold their names. Any other label in the header is a plain label; one merged down, like "Region" over A1:A2, just fills the header's height. A merge with no value is layout, and is ignored.

// The header starts as one row. Each group label in it needs one row of names
// under it; if that row holds a group label too (a year over quarters), one more.
function countHeaderRows(merges, top, isGroup) {
  let depth = 1;
  for (let grown = true; grown; ) {
    grown = false;
    for (const m of merges) {
      if (!isGroup(m) || m.top < top || m.top >= top + depth) continue;
      const needed = m.bottom - top + 2; // the label's rows plus one row of names
      if (needed > depth) { depth = needed; grown = true; }
    }
  }
  return depth;
}

The loop repeats because a new header row can hold a group label of its own. The caller caps the result at maxRows (3: year, quarter and measure), so that a stray merge cannot swallow data rows into the header.

Step 2: check the header

Some headers would give wrong names, so three checks run before any record is read. A merge over every named column is read as a title. Every column under a group label needs a name below it. And in a lower header row, a value may sit under a group label, or under empty cells (a name aligned to the bottom row, like "Region" in A2 with A1 empty), but not under a plain label: "Ana" under "Name" means the row is data, and the merge that pulled it into the header was a title or just layout. Every such cell is reported, so the user sees them all at once.

// Returns the problems that would give wrong column names.
function checkHeader({ headerRows, width, groups, valueAt, mergeAt, label, isGroup, excelAddress, origin }) {
  const problems = [];
  const named = [...Array(width).keys()].filter((c) => headerRows.some((r) => label(r, c) !== ""));
  for (const g of groups) {
    const text = JSON.stringify(label(g.top, g.left));
    // Over every named column, it would start every name: read it as a title.
    if (named.length > 1 && g.left <= named[0] && g.right >= named.at(-1)) {
      problems.push({ range: g.address, reason: `${text} spans the whole table, so it looks like a title`,
        hint: "pass the row index of the column names as headerTop" });
      continue;
    }
    // Every column under a group label needs a name in a header row below it.
    for (let c = g.left; c <= Math.min(g.right, width - 1); c++) {
      if (headerRows.some((r) => r > g.bottom && label(r, c) !== "")) continue;
      problems.push({ range: g.address, reason: `${text} has no column name under it in ${excelAddress(g.bottom + 1, c)}`,
        hint: "type the missing name, or unmerge the label" });
    }
  }
  // A plain label is a header value that is not a group label. A value under a
  // plain label ("Ana" under "Name") means the row is data, pulled into the header
  // by a merge that is a title or layout.
  for (const r of headerRows.slice(1)) {
    const cause = groups.find((g) => g.top < r && g.bottom + 1 >= r)?.address ?? "a merge above it";
    const row = origin.r + r + 1;
    for (let c = 0; c < width; c++) {
      if (isEmpty(valueAt(r, c)) || mergeAt(r, c)) continue;
      const above = headerRows.filter((a) => a < r && label(a, c) !== "").at(-1);
      if (above === undefined || isGroup(mergeAt(above, c))) continue;
      problems.push({ range: excelAddress(r, c),
        reason: `${JSON.stringify(valueAt(r, c))} is under the plain label ${JSON.stringify(label(above, c))} (${excelAddress(above, c)}), so row ${row} looks like data`,
        hint: `${cause} made row ${row} part of the header. Unmerge it if it is layout; pass headerTop if it is a title; type one name in one cell if both cells are one name` });
    }
  }
  return problems;
}

The same check refuses a plain label over one column with a name under it, such as "Total" over "Amount" next to a merged group. We chose to refuse it: from the cells alone, it has the same shape as "Name" over "Ana", and reading a data row as names is worse than asking the user to type "Total Amount" in one cell.

Step 3: name the columns

readHeader puts the pieces together. For each column, it takes what Excel shows in each header row, from top to bottom, and joins the labels with a space. A label merged down counts once, and line breaks inside a cell (Alt+Enter) become spaces.

// Reads a header that starts at row index `top` and may have up to maxRows rows.
// A cell merged across columns ("Q1" over C1:D1) is a group label, so the row
// below it is part of the header too. Returns one name per column ("Q1 Revenue"),
// the parts of each name (["Q1", "Revenue"]), the number of header rows, notes and
// problems. If any problem has refuse: true, the header was not read.
function readHeader(rows, merges, top, origin, maxRows = 3) {
  const excelAddress = (r, c) => XLSX.utils.encode_cell({ r: origin.r + r, c: origin.c + c });
  const valueAt = (r, c) => rows[r]?.[c] ?? "";
  const mergeAt = (r, c) => merges.find((m) => m.top <= r && r <= m.bottom && m.left <= c && c <= m.right);
  // What Excel shows in a cell: for any cell of a merge, the first cell's value.
  const shown = (r, c) => { const m = mergeAt(r, c); return m ? valueAt(m.top, m.left) : valueAt(r, c); };
  // Line breaks (Alt+Enter) and double spaces inside a label become one space.
  const label = (r, c) => String(shown(r, c)).replace(/\s+/g, " ").trim();
  // A group label: a merge across columns with a value. An empty merge is layout.
  const isGroup = (m) => m !== undefined && m.right > m.left && !isEmpty(valueAt(m.top, m.left));
  const refuse = (list) => ({ depth: 0, columns: [], parts: [], notes: [], problems: list.map((p) => ({ ...p, refuse: true })) });
  const start = excelAddress(Math.min(top, Math.max(rows.length - 1, 0)), 0);
  if (top >= rows.length) return refuse([{ range: start, reason: `headerTop ${top} is past the last row of the sheet` }]);

  const depth = countHeaderRows(merges, top, isGroup);
  if (depth > maxRows) return refuse([{ range: start, reason: `the header would have ${depth} rows; this code reads at most ${maxRows}` }]);
  // The file ends inside the header, such as a group label in its last row.
  if (top + depth > rows.length) return refuse([{ range: start, reason: `no data rows under the ${depth}-row header` }]);
  const headerRows = [...Array(depth).keys()].map((i) => top + i);

  // Names: the labels of each column from top to bottom, joined with a space.
  // A label merged down ("Region" over A1:A2) counts once.
  const labelsOf = (c) => {
    const labels = [];
    let previous;
    for (const r of headerRows) {
      const m = mergeAt(r, c);
      if (m !== undefined && m === previous) continue;
      previous = m;
      if (label(r, c) !== "") labels.push(label(r, c));
    }
    return labels;
  };
  const lastColumn = Math.max(0, ...headerRows.map((r) => rows[r]?.length ?? 0));
  const parts = [...Array(lastColumn).keys()].map(labelsOf);
  const width = parts.findLastIndex((labels) => labels.length > 0) + 1;
  if (width === 0) return refuse([{ range: start, reason: "the header row has no column names; if the header is lower, pass its row index as headerTop" }]);
  parts.length = width;
  const groups = merges.filter((m) => isGroup(m) && m.top >= top && m.top < top + depth && m.left < width);

  const problems = checkHeader({ headerRows, width, groups, valueAt, mergeAt, label, isGroup, excelAddress, origin });
  if (problems.length > 0) return refuse(problems);
  // Rows past the header that are all empty do not count as data.
  if (rows.slice(top + depth).every((row) => row.every(isEmpty))) {
    return refuse([{ range: start, reason: `no data rows under the ${depth}-row header` }]);
  }

  // A group label over the first named column may be a title over part of the
  // table ("Sales 2026" over A1:C1). It is read as a group, with a note.
  const first = parts.findIndex((labels) => labels.length > 0);
  const notes = groups.filter((g) => g.top === top && g.left <= first).map((g) => ({
    range: g.address, reason: `${JSON.stringify(label(g.top, g.left))} starts the names of the columns under it; if it is a title, pass the row index of the column names as headerTop` }));

  // A value stored in a cell that a header merge covers is hidden in Excel and is
  // not used in any name. It is reported; the header is still read.
  for (const m of merges.filter((m) => m.left < width)) {
    for (const r of headerRows) {
      if (r < m.top || r > m.bottom) continue;
      for (let c = m.left; c <= m.right; c++) {
        if ((r === m.top && c === m.left) || isEmpty(valueAt(r, c))) continue;
        problems.push({ range: m.address, reason: `hides ${JSON.stringify(valueAt(r, c))} in ${excelAddress(r, c)}`,
          hint: "only the first cell's value is used in the name" });
      }
    }
  }
  return { depth, columns: parts.map((labels) => labels.join(" ")), parts, notes, problems };
}

parts keeps the pieces of each name (["Q1", "Revenue"]): use them as the key if you build nested fields. Two things come back without stopping the import: a note when a group label covers the first named column (it may be a title over part of the table, which would start every name it covers), and a problem for a value hidden under a header merge, which Excel does not show and the names do not use.

Step 4: read the table

readGroupedTable reads the header, handles merges in the data with fillMerges, and turns each data row into a record with the row number the user sees in Excel.

// Reads an .xlsx file whose header may have up to maxRows rows into records.
// headerTop: index of the first header row. 0 is the first row SheetJS reads
// (Excel row 1 for most files), 1 the row under it.
function readGroupedTable(bytes, headerTop = 0, maxRows = 3) {
  const { rows, merges, origin } = readXlsx(bytes);
  const header = readHeader(rows, merges, headerTop, origin, maxRows);
  if (header.problems.some((p) => p.refuse)) return { columns: [], records: [], notes: [], problems: header.problems };
  const { columns, depth } = header;
  const width = columns.length;
  // The header cells of column c, such as "D1:D2", for messages.
  const headerCells = (c) => XLSX.utils.encode_range({
    s: { r: origin.r + headerTop, c: origin.c + c }, e: { r: origin.r + headerTop + depth - 1, c: origin.c + c } });

  // Merges in the data: the same rules as for a one-row header.
  const firstData = headerTop + depth;
  const filled = fillMerges(rows, merges, firstData, width, origin);
  const problems = [...header.problems, ...filled.problems];
  const isData = (r) => r >= firstData && !filled.skipRows.has(r) &&
    !rows[r].slice(0, width).every(isEmpty);
  const seen = new Set();
  columns.forEach((name, c) => {
    if (name === "") {
      if (rows.some((row, r) => isData(r) && !isEmpty(row[c]))) {
        problems.push({ range: headerCells(c), reason: "has data but no column name" });
      }
      return;
    }
    // Typed twice ("Q1" over two groups): the later column would overwrite the
    // first in each record, so the file is refused.
    if (seen.has(name.toLowerCase())) {
      problems.push({ range: headerCells(c), reason: `repeats the column name ${JSON.stringify(name)}`, refuse: true });
    }
    seen.add(name.toLowerCase());
  });

  const notes = [...header.notes, ...filled.notes];
  if (problems.some((p) => p.refuse)) return { columns: [], records: [], notes, problems };
  const records = [];
  rows.forEach((row, r) => {
    if (!isData(r)) return;
    const values = Object.fromEntries(
      columns.flatMap((name, c) => (name ? [[name, row[c] ?? ""]] : [])));
    records.push({ row: origin.r + r + 1, values });
  });
  return { columns: columns.filter((name) => name !== ""), records, notes, problems };
}

A name used twice, ignoring case (the same group label typed over two groups gives two "Q1 Revenue" columns), refuses the file: the second column would overwrite the first in every record. With a one-row header and no group labels, the result is the same as readMergedTable from the previous post (a test checks this).

Here it is on the sales report:

// file: a File from <input type="file">, inside an async change handler.
let table;
try {
  table = readGroupedTable(await file.arrayBuffer());
} catch (error) {
  // readXlsx throws a TypeError when the bytes do not start like a zip archive
  // (an .xlsx file is one), and SheetJS throws for a damaged file.
  console.error(error);
  table = { columns: [], records: [], notes: [], problems: [{ range: null, reason: "the file could not be read as .xlsx" }] };
}
const { columns, records, notes, problems } = table;

columns;
// [ 'Region', 'Rep', 'Q1 Revenue', 'Q1 Cost', 'Q2 Revenue', 'Q2 Cost' ]
records[1];
// { row: 4, values: { Region: 'North', Rep: 'Bo', 'Q1 Revenue': 90, 'Q1 Cost': 50, 'Q2 Revenue': 80, 'Q2 Cost': 40 } }
notes.map((n) => `${n.range}: ${n.reason}`); // [ 'A3:A4: "North" copied into A4' ]
problems; // []

Each Revenue column now says which quarter it belongs to, so your mapping screen can offer Q1 Revenue as its own field. Show the column names in your preview too: two cases below give wrong names that no check can catch.

Headers it refuses

// title, hole and layout hold the bytes of three small .xlsx files
// that this code refuses, with no records:
// title: "Sales 2026" merged across A1:C1, above the column names in row 2.
// hole: "Q1" across B1:C1, with "Revenue" in B2 and nothing in C2.
// layout: "Note" merged across B1:C1 only to make room; row 2 is Ana's data.
const reasons = (table) => table.problems.map((p) => `${p.range}: ${p.reason}`);

const titled = readGroupedTable(title);
reasons(titled);
// [ 'A1:C1: "Sales 2026" spans the whole table, so it looks like a title' ]
titled.problems[0].hint; // 'pass the row index of the column names as headerTop'
readGroupedTable(title, 1).columns; // [ 'Name', 'Rep', 'City' ]
reasons(readGroupedTable(hole));
// [ 'B1:C1: "Q1" has no column name under it in C2' ]
const laidOut = readGroupedTable(layout);
reasons(laidOut);
// [ 'A2: "Ana" is under the plain label "Name" (A1), so row 2 looks like data' ]
laidOut.problems[0].hint;
// 'B1:C1 made row 2 part of the header. Unmerge it if it is layout; pass headerTop if it is a title; type one name in one cell if both cells are one name'

A column with data but no name is reported too, as in the previous post, and its data is left out.

To sum up what comes back: a problem with refuse: true means nothing was imported. A problem without it means the records came back, but show it as a warning before you save them. A note is for information. Every item has a range (an Excel address, or null if the whole file failed) and a reason; header problems also have a hint for the user. Show the reason next to the cell and the hint under it.

What this does not cover

  • Group labels typed once without a merge. If "Q1" is in C1 and D1 is just empty, there is no merge to read, so the header is one row. Filling "Q1" to the right would be a guess; ask the user to merge or repeat the label.
  • Labels centered with "Center Across Selection". This Excel alignment centers a label over several cells without merging them (UW-Madison KnowledgeBase, updated 2026-09-01); the file stores it as the centerContinuous alignment (Microsoft's MS-EXSPXML spec, last updated 2020-10-13). There is no merge to read, so the header is one row: on the sales report, the code returns the columns Region, Rep, Q1 and Q2, and reports D1 as a column with data but no name. Ask the user to merge the labels or type full names.
  • A layout merge over text data in every column it covers. If an Id column is merged down and "Contact" is merged over two text columns for looks, the first data row is read as names ("Contact Ana"). Show the column names in your preview so the user can catch it.
  • A real group over every column. "Contact" over First, Last and Email in a three-column table is refused as a title. Passing headerTop 1 reads the names without "Contact".
  • A title over only some columns. "Sales 2026" merged over A1:C1 above four names is read as a group label, so the names start with it ("Sales 2026 Name"). You get a note, not a problem. If you know where the names are, pass headerTop.
  • Data right of the last named column is not read, and no problem is reported, as in the previous post.
  • Group labels stored as dates. A month label such as "Jan 2026" is stored as a number with a date format, so it arrives as 46023 and the names become 46023 Revenue. Convert it as in our post on reading Excel dates, or ask the user to type the label as text.
  • Notes beside the table. A note merged across two cells to the right of the header row is taken for a group label, so the file is refused with problems that point at the note. Ask the user to delete it.
  • CSV and .xls files, other sheets and hidden rows, as in the previous post.
