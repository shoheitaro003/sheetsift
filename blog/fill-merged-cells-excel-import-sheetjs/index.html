Fill merged cells in Excel imports with SheetJS

2026-11-24

A customer uploads an order list where "North" is merged over three rows. Your importer reads it with SheetJS and gets "North" for the first order only; the next two have no region. A footnote merged across the bottom row arrives as one more order.

By the end of this post you will have readMergedTable(bytes), about 150 lines on top of SheetJS. It copies merged labels such as a region into every row they cover, skips title and footnote rows, and lists the merges it should not guess about, by their Excel address. It handles .xlsx files with a one-row header. Every result quoted below is checked by our test file (the tests named md:) in Node 22 with SheetJS 0.20.3.

The problem

Here is the file. Each merged range is drawn as one cell:

ABCD
1RegionRepInvoiceAmount
2North
(A2:A4)		AnaINV-1100
3BoINV-290
4CyINV-370
5SouthDiINV-460
6Note: amounts in EUR (A6:D6)

Read the usual way:

// Orders.xlsx: "North" is merged over A2:A4, "Note: amounts in EUR" over A6:D6.
const sheet = workbook.Sheets[workbook.SheetNames[0]];
const records = XLSX.utils.sheet_to_json(sheet, { defval: "" });
records.length;          // 5
records[1].Region;       // ''  (Bo's row: "North" is stored in A2 only)
records[4].Region;       // 'Note: amounts in EUR'  (the footnote, read as an order)
sheet["!merges"].length; // 2

In the file, a merged range stores its value in its first (top-left) cell only; A3 and A4 hold nothing. The merge itself is stored separately, and SheetJS returns the list of merged ranges in sheet["!merges"]. That list is all you need to put "North" back into rows 3 and 4.

But you cannot fill every merge. Copying a total of 150 merged over two invoice lines gives 300 when you add up the lines. So the code below decides by the shape of the merge and the type of its value.

Step 1: read the rows and the merges

All the code in this post goes in one module; export readMergedTable from it.

// npm install https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz
import * as XLSX from "xlsx";

const isEmpty = (value) => String(value ?? "").trim() === "";
const isLabel = (value) => typeof value === "string" && value.trim() !== "";

// Reads the first sheet of an .xlsx file.
// rows: one array of cells per row. merges: the merged ranges.
// Both count from 0 at the first cell of the sheet's stored range (origin).
function readXlsx(bytes) {
  const data = bytes instanceof ArrayBuffer ? new Uint8Array(bytes) : bytes;
  // An .xlsx file is a zip archive, and zip archives start with the bytes "PK".
  if (data[0] !== 0x50 || data[1] !== 0x4b) throw new TypeError("not an .xlsx file");
  const workbook = XLSX.read(data);
  const sheet = workbook.Sheets[workbook.SheetNames[0]];
  if (!sheet?.["!ref"]) return { rows: [], merges: [], origin: { r: 0, c: 0 } };
  const origin = XLSX.utils.decode_range(sheet["!ref"]).s;
  const rows = XLSX.utils.sheet_to_json(sheet, {
    header: 1, defval: "", blankrows: true, raw: true });
  const merges = (sheet["!merges"] ?? []).map((m) => ({
    address: XLSX.utils.encode_range(m), // "A2:A4", for messages
    top: m.s.r - origin.r, bottom: m.e.r - origin.r,
    left: m.s.c - origin.c, right: m.e.c - origin.c,
  }));
  return { rows, merges, origin };
}

Why each option is there:

  • header: 1 returns each row as an array, so row and column positions match the sheet. defval: "" fills missing cells and blankrows: true keeps empty rows, so rows[r][c] is always the same cell as in the file.
  • raw: true returns stored values, not the text Excel displays: a number stays a number. Dates arrive as serial numbers; our post on reading Excel dates converts them.
  • The stored range of a sheet, in sheet["!ref"], is the block of cells the file uses, such as A1:D6. It does not have to start at A1, so the code counts from its first cell (origin) and moves each merge by the same amount. Each merge keeps its address, because that is what the user sees in Excel.

The first check refuses anything that is not a zip archive, such as a CSV or an old .xls file, with a TypeError. A CSV has no merges at all, so this code would have nothing to fill.

Step 2: decide what each merge means

Below the header, the shape of a merge and the type of its value tell you what it is. Only one case is safe to fill: text merged down one column.

Merge in the dataUsually meansWhat fillMerges does
Text in one column, several rows (A2:A4)a group label, such as a regioncopies it into each row; adds a note
A number, date or boolean in one column, several rows (D2:D3)one total for several lineskeeps it in the first row only; reports a problem
Text across the whole table (A6:D6)a title, section name or footnoteskips the rows; adds a note
A number across the whole tablemaybe a grand totalskips the rows; reports a problem
Some of the columns (B4:C4), one row or morea long text that needed room, or layoutkeeps the value in the first cell; reports a problem. An empty merge is left alone
Starts in the header row, ends in the dataa mistake, or a header with more rowsreports a problem, unless the rows it reaches are empty; the records are still returned
 
// Fills the merges in the data that are safe to fill; reports the others.
// Changes rows in place. firstData: index of the first row under the header.
// width: number of columns in the table.
function fillMerges(rows, merges, firstData, width, origin) {
  const notes = [];
  const problems = [];
  const skipRows = new Set();
  const excelAddress = (r, c) => XLSX.utils.encode_cell({ r: origin.r + r, c: origin.c + c });
  // Only the table's columns count: a stray comment further right does not make a row data.
  const blank = (row) => row.slice(0, width).every(isEmpty);
  for (const m of merges) {
    if (m.bottom < firstData) continue; // in or above the header row
    if (m.top >= rows.length) continue;  // below the last row: nothing to read
    if (m.left >= width) continue;       // right of the table, such as a logo box
    if (m.top < firstData) {
      // A header cell merged down into the data. Harmless only if those rows are empty.
      const into = rows.slice(firstData, m.bottom + 1);
      if (!into.every(blank)) {
        const reason = "runs from the header into the data; the header may have two rows";
        problems.push({ range: m.address, reason });
      }
      continue;
    }
    const value = rows[m.top][m.left];
    const last = Math.min(m.bottom, rows.length - 1);
    // The user sees only the first cell's value. A value stored in another cell of
    // the range is hidden in Excel, so it is reported and not imported.
    for (let r = m.top; r <= last; r++) {
      for (let c = m.left; c <= m.right; c++) {
        if ((r === m.top && c === m.left) || isEmpty(rows[r][c])) continue;
        problems.push({ range: m.address, reason: `hides ${JSON.stringify(rows[r][c])} in ${excelAddress(r, c)}` });
        rows[r][c] = "";
      }
    }
    const height = last - m.top + 1; // rows that exist, if the merge runs past the end
    const span = m.right - m.left + 1;
    if (span === 1 && isLabel(value)) {
      // Text in one column over several rows: a group label. Copy it down, except
      // into rows that are empty in the file (those are skipped, not imported).
      const filled = [];
      for (let r = m.top + 1; r <= last; r++) {
        if (blank(rows[r])) continue;
        rows[r][m.left] = value;
        filled.push(excelAddress(r, m.left));
      }
      if (filled.length > 0) {
        notes.push({ range: m.address, reason: `${JSON.stringify(value)} copied into ${filled.join(", ")}` });
      }
    } else if (span === 1) {
      // A number, date or boolean over several rows, such as one total for two
      // invoice lines. Copying it would count it twice.
      if (!isEmpty(value) && last > m.top) {
        problems.push({ range: m.address, reason: `covers ${height} rows; ${JSON.stringify(value)} is read into ${excelAddress(m.top, m.left)} only` });
      }
    } else if (m.left === 0 && m.right >= width - 1) {
      // One cell across the whole table: a title, a section name or a footnote.
      for (let r = m.top; r <= last; r++) skipRows.add(r);
      const first = origin.r + m.top + 1;
      const where = last > m.top ? `rows ${first}-${origin.r + last + 1}` : `row ${first}`;
      // Text is skipped quietly; a number across the table (a grand total?) is reported.
      const list = isLabel(value) || isEmpty(value) ? notes : problems;
      list.push({ range: m.address, reason: `${where} skipped: ${JSON.stringify(value)} spans the table` });
    } else if (!isEmpty(value)) {
      // Several columns but not the whole table: the value belongs to one of them,
      // and only the user knows which. An empty merge, kept for layout, is left alone.
      const size = height > 1 ? `${height} rows and ${span} columns` : `${span} columns`;
      problems.push({ range: m.address, reason: `covers ${size}; ${JSON.stringify(value)} is read into ${excelAddress(m.top, m.left)} only` });
    }
  }
  return { notes, problems, skipRows };
}

A few details the table leaves out, each covered by a test:

  • Text means any text. TBD merged over two amounts is copied into both, like a region. Your amount check should then reject TBD in both rows.
  • Hidden values. A program can write values into the other cells of a merge, but Excel shows only the first one. fillMerges reports such a value and clears it, so the import matches what the user sees.
  • Empty rows inside a merged label are not filled, so they are still skipped instead of becoming records with only a region.
  • The table's columns run from the first column of the stored range to the last column with a name. Cells further right are ignored: a stray comment there does not turn an empty row into a record, and a merge there, such as a logo box, is skipped.

Step 3: read the table

readMergedTable reads the header row, refuses headers it cannot read, runs fillMerges and builds one record per data row, with the row number the user sees in Excel.

// Reads an .xlsx file with a one-row header into records.
// headerTop: index of the header row, counted from the first row of the stored
// range (0 for most files). The header row must not be merged across columns.
function readMergedTable(bytes, headerTop = 0) {
  const { rows, merges, origin } = readXlsx(bytes);
  const headerCell = (c) => XLSX.utils.encode_cell({ r: origin.r + headerTop, c: origin.c + c });
  const columns = (rows[headerTop] ?? []).map((name) => String(name).trim());
  const width = columns.findLastIndex((name) => name !== "") + 1;
  if (width === 0) {
    const reason = "the header row has no column names; if the header is lower, pass its index as headerTop";
    return { columns: [], records: [], notes: [], problems: [{ range: headerCell(0), reason }] };
  }
  const problems = [];
  // A header cell merged across columns ("Q1" over C1:D1) means a header with two
  // or more rows. This code reads one header row, so it reports the file instead.
  for (const m of merges) {
    if (m.top <= headerTop && m.bottom >= headerTop && m.right > m.left && m.left < width) {
      problems.push({ range: m.address, reason: "header cell merged across columns; this code reads a one-row header only" });
    }
  }
  if (problems.length > 0) return { columns: [], records: [], notes: [], problems };

  const firstData = headerTop + 1;
  const filled = fillMerges(rows, merges, firstData, width, origin);
  problems.push(...filled.problems);
  const isData = (r) => r >= firstData && !filled.skipRows.has(r) &&
    !rows[r].slice(0, width).every(isEmpty);
  columns.length = width;
  columns.forEach((name, c) => {
    if (name === "" && rows.some((row, r) => isData(r) && !isEmpty(row[c]))) {
      problems.push({ range: headerCell(c), reason: "has data but no column name" });
    }
  });
  const seen = new Set();
  columns.forEach((name, c) => {
    if (name === "") return;
    // "Email" and "email" would become one field in most mappings: report it.
    if (seen.has(name.toLowerCase())) {
      problems.push({ range: headerCell(c), reason: `repeats the column name ${JSON.stringify(name)}` });
    }
    seen.add(name.toLowerCase());
  });

  const records = [];
  rows.forEach((row, r) => {
    if (!isData(r)) return;
    // Object.fromEntries defines own properties, so a column named "__proto__" is safe.
    // With a repeated name, the later column wins; the problem above says so.
    const values = Object.fromEntries(
      columns.flatMap((name, c) => (name ? [[name, row[c] ?? ""]] : [])));
    records.push({ row: origin.r + r + 1, values }); // the row number the user sees in Excel
  });
  return { columns: columns.filter((name) => name !== ""), records, notes: filled.notes, problems };
}

It reports three header problems besides the merges:

  • A header cell merged across columns, such as Q1 over C1:D1. That usually means a header with two rows (Q1 over Revenue and Cost), which this code does not read. Rather than guess the column names, it returns the problem and no records.
  • A column with data but no name. A column with neither is dropped without a message.
  • A name used twice, ignoring case (Name and name). The later column overwrites the earlier one in the record, so the user should rename one.

Here it is on the order list, with the try/catch that turns an unreadable file into a problem too:

let table;
try {
  table = readMergedTable(await file.arrayBuffer());
} catch (error) {
  // readXlsx throws a TypeError for a file that is not .xlsx,
  // and SheetJS throws for a damaged one.
  // Log the original error, so a bug in your own code is not mistaken for a bad file.
  console.error(error);
  const reason = "the file could not be read as .xlsx";
  table = { columns: [], records: [], notes: [], problems: [{ range: null, reason }] };
}
const { columns, records, notes, problems } = table;

records.map((r) => `${r.row}: ${r.values.Region}, ${r.values.Rep}`);
// [ '2: North, Ana', '3: North, Bo', '4: North, Cy', '5: South, Di' ]
notes.map((n) => `${n.range}: ${n.reason}`);

//   'A6:D6: row 6 skipped: "Note: amounts in EUR" spans the table' ]

And on an invoice file where two merges should not be filled:

// Invoices.xlsx: header Customer, Invoice, Line, Amount (A1:D1). Merged in the data:
// "Acme" over A2:A3, 150 over D2:D3 (one amount for two lines),
// and "Paid by card, see note" over B4:C4.
problems.map((p) => `${p.range}: ${p.reason}`);

The amount 150 stays on the first line, so the invoice still adds up to 150. The payment note stays in the Invoice column, where the user can see it is in the wrong place.

Show the notes in your import preview, so the user can see that "North" was copied and row 6 was skipped. Import only when problems is empty, or when the user has fixed or accepted each one. If the header is not the first row of the stored range, pass its index as headerTop, counting from 0 at the first row of the stored range: a header in Excel row 3 of a range that starts at A1 is headerTop = 2. Our post on finding the header row finds it. A title merged across the rows above the header is then ignored.

What this does not cover

  • Headers with two or more rows. They are refused, as described in step 3.
  • CSV and .xls files. A CSV stores no merges, so a region typed once over three rows arrives as a value followed by empty cells, the same as cells nobody filled in. Fill such a column only after the user says it is grouped.
  • A label on a row of its own. If "North" sits alone in row 2, merged over A2:A4, and the orders start in row 3, row 2 becomes a record with only a region. Your required-field checks will catch it.
  • One-column tables. With a single column, a footnote merged down that column looks like a group label, so it is read as a record, not skipped.
  • Section labels as data. A row like Europe across the table is skipped. If the rows below belong to it, add it as a column yourself.
  • Empty columns left of the table. If the stored range starts at column A but the table starts at B, a footnote merged over B:E does not reach the first column, so it is reported instead of skipped. Ask the user to delete the empty column.
  • Other sheets and hidden rows. Only the first sheet is read, and hidden rows are read like any other.
  • Blank cells that are not merged. They stay empty. Our post on placeholder values shows how to report them in required columns.
