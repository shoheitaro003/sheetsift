Find CSV rows broken by unquoted commas in JavaScript

2026-11-13

A customer uploads a CSV with the header Name,Company,Amount. One row reads Ken Mori,Acme, Inc,120. Whoever wrote the file did not put quotes around Acme, Inc, so the row has four values for three columns: Inc lands in Amount and 120 is dropped, or your import fails with "wrong number of fields" and no hint why.

By the end of this post you will have checkCsv(text), a small module with no dependencies. It returns the rows that are safe to import and, for every other row, an issue with its line number, the cause, and a repaired row when exactly one repair is explained by the data. Nothing is fixed without a person saying yes. Every function and every result below is checked by our test file in Node 22.

Why the parser cannot fix this on its own

const header = "Name,Company,Amount".split(",");
const row = "Ken Mori,Acme, Inc,120".split(",");
row.length; // 4, but the header has 3
Object.fromEntries(header.map((name, i) => [name, row[i]]));
// { Name: "Ken Mori", Company: "Acme", Amount: " Inc" } and 120 is gone

A better parser does not help. In the CSV this post handles (and step 1 parses), a value that contains the delimiter is wrapped in double quotes, and a quote inside such a value is written twice ("Ross ""M"" Ltd"). Without the quotes, Acme, Inc is two values as far as a parser can tell. The rest of the file can tell more: if every other row has a number in Amount and no row starts a value with a space, then Acme + , Inc is far more likely than a fourth column. The code below turns that reasoning into rules you can test; its parts go into one module, in order.

Step 1: parse, and keep line numbers and quote problems

To tell the user where a problem is, you need the line it is on in their file. A record (one row of values) can span several lines when a quoted value contains a line break, so counting records is not enough. parseRecords keeps the physical line each record starts on, the way a text editor numbers lines:

// Reads CSV text into records. Each record keeps the line it starts on and
// a list of quote problems, so nothing odd is accepted without a note.
function parseRecords(text, delimiter = ",", limit = Infinity) {
  const records = [];
  let fields = [], field = "", line = 1, start = 1, problems = [];
  let quoted = false, closed = false, quoteLine = 0, spaces = "";
  const note = (problem) => { if (!problems.includes(problem)) problems.push(problem); };
  const endField = () => { fields.push(field); field = ""; closed = false; spaces = ""; };
  const endRecord = () => {
    endField();
    records.push({ line: start, fields, problems });
    fields = [];
    problems = [];
  };
  for (let i = 0; i < text.length && records.length < limit; i++) {
    const c = text[i];
    if (quoted) {
      if (c === '"' && text[i + 1] === '"') { field += '"'; i++; }
      else if (c === '"') { quoted = false; closed = true; }
      else {
        if (c === "\n" || (c === "\r" && text[i + 1] !== "\n")) line++;
        field += c;
      }
    } else if (c === delimiter) {
      endField();
    } else if (c === "\n" || c === "\r") {
      if (c === "\r" && text[i + 1] === "\n") i++;
      endRecord();
      start = ++line;
    } else if (c === '"' && field.trim() === "" && !closed) {
      quoted = true; // spaces before an opening quote are dropped: a, "b, c"
      quoteLine = line;
      field = "";
    } else if (closed && (c === " " || c === "\t")) {
      spaces += c; // kept only if more text follows the closing quote
    } else {
      if (closed) { note("text-after-quote"); field += spaces; spaces = ""; }
      if (c === '"') note("stray-quote");
      field += c;
    }
  }
  if (records.length >= limit) return records;
  if (quoted) {
    // The quote never closed: the rest of the file became one value.
    fields.push(field);
    const lastLine = /[\r\n]$/.test(text) ? line - 1 : line;
    records.push({ line: start, fields, problems: ["unclosed-quote"], quoteLine, lastLine });
  } else if (field !== "" || fields.length || closed) {
    endRecord();
  }
  return records;
}

const isBlank = (record) => record.fields.length === 1 && record.fields[0] === "";

It reads one character at a time, because quotes change the meaning of everything after them. It also handles four quote cases; the first two and the last are noted, because a careful importer should not accept them silently:

  • A stray quote, as in Fox 5" Ltd: a quote inside a value that did not start with one. The value is kept as written, which is usually right, and flagged.
  • Text after a closing quote, as in "Zeta" Corp. The parts are joined to Zeta Corp and flagged.
  • Spaces around a quoted value, as in "Yui", "Acme, Inc", 49. Some files are written this way, so spaces before an opening quote and after a closing quote are dropped without a note.
  • A quote that never closes. Everything from there to the end of the file becomes one value. The record remembers where the quote opened, so the message can point at it.

A short trace of Zed Roe,"Zeta" Corp,8: the quote after the first comma opens a quoted value, Zeta is read inside it, and the next quote closes it. The space after it is held back in spaces; if a delimiter came next it would be dropped, but C comes, so the space and Corp are added and the record gets the note text-after-quote.

Line breaks can be \r\n (Windows), \n, or a lone \r (old Mac exports); all three count as one line, inside and outside quotes. limit stops after that many records, which step 2 uses.

Step 2: guess the delimiter, and say when you are not sure

A semicolon file read with commas also gives the "wrong" number of values on many rows, so settle the delimiter first. For each candidate, guessDelimiter parses the first 30 records and scores the share of rows with as many values as the first row:

function guessDelimiter(text, candidates = [",", ";", "\t", "|"]) {
  const scores = candidates.map((delimiter) => {
    const records = parseRecords(text.replace(/^\uFEFF/, ""), delimiter, 30)
      .filter((r) => !isBlank(r));
    const width = records.length ? records[0].fields.length : 0;
    const rest = records.slice(1);
    const same = rest.filter((r) => r.fields.length === width).length;
    const score = width < 2 ? 0 : rest.length ? same / rest.length : 0.5;
    return { delimiter, score };
  });
  scores.sort((a, b) => b.score - a.score);
  const [best, next] = scores;
  if (best.score === 0) return { delimiter: ",", sure: false };
  // Sure when most rows agree and no other delimiter comes close.
  return { delimiter: best.delimiter, sure: best.score > 0.5 && next.score <= best.score / 2 };
}

It is sure when more than half of the rows agree and no other candidate scores more than half as well. One broken row in a small file does not make it unsure; a file where most rows are broken does. Our tests give:

When it is not sure, show the first rows split both ways and let the user pick.

Step 3: learn what each column looks like

To judge a repair you need to know what a column normally holds. columnKinds looks only at rows that parsed cleanly with the right number of values:

// A plain number, with or without thousands separators: 49, -1,234.50
const NUMBER = /^[-+]?(\d+|\d{1,3}(,\d{3})+)(\.\d+)?$/;

// "number" if every value in the column is a number, "text" if none is,
// "any" if it is mixed or has fewer than two values.
function columnKinds(rows, width) {
  return Array.from({ length: width }, (_, column) => {
    const values = rows.map((r) => r.fields[column].trim()).filter(Boolean);
    if (values.length < 2) return "any";
    const numbers = values.filter((v) => NUMBER.test(v)).length;
    if (numbers === values.length) return "number";
    return numbers === 0 ? "text" : "any";
  });
}

function fits(fields, kinds) {
  return fields.every((value, column) => {
    const v = value.trim();
    if (!v || kinds[column] === "any") return true;
    return (kinds[column] === "number") === NUMBER.test(v);
  });
}

Three kinds are enough for the rules in step 4. A column is "number" when every value is a plain number, and "text" when no value is, so a number landing in a Company column counts as wrong. Mixed columns, and columns with fewer than two values, accept anything. Blank cells always fit.

Step 4: find a join that the data explains

A row with k extra values was split at k commas too many. If they are next to each other, joining k + 1 neighbouring values back together repairs the row. findJoins tries every position:

// Which run of fields, joined back with the delimiter, gives the right width?
// A join counts only if something explains it: every piece after the first
// starts with a space (a comma inside a sentence), or the joined value is a
// grouped number such as 1,234 in a number column. It must also fit the kinds.
function findJoins(fields, width, kinds, delimiter, spacedFile) {
  const extra = fields.length - width;
  const joins = [];
  for (let at = 0; at + extra < fields.length; at++) {
    const pieces = fields.slice(at, at + extra + 1);
    const joined = pieces.join(delimiter);
    const prose = !spacedFile && delimiter !== "\t" &&
      pieces.slice(1).every((p) => /^ \S/.test(p));
    const grouped = delimiter === "," && kinds[at] === "number" &&
      NUMBER.test(joined.trim());
    const result = [...fields.slice(0, at), joined, ...fields.slice(at + extra + 1)];
    if ((prose || grouped) && fits(result, kinds)) joins.push({ at, result });
  }
  return joins;
}

Fitting the column kinds is not enough. In Ken Mori,Acme, Inc,Osaka,120, joining Ken Mori,Acme also leaves a row whose kinds fit, because every text column accepts Inc. So a join must also be explained by one of two patterns:

  • A comma inside a sentence. When people type a comma in a name or a note, a space usually follows it, as in Acme, Inc. The rule assumes the file's own delimiters are not followed by a space, and checks that on the clean rows first: if any value after the first column starts with a space (a file written as a, b, c), the rule is switched off. It is also off for tab files.
  • A thousands separator in a number column: 1 + 234 joined is 1,234, a valid grouped number. 12,5 is not (it would be a decimal comma), so it is not joined. A grouped join can still be wrong, since Porto,1,234 may also be a row shifted by one column, which is why it is only a suggestion.

Several commas next to each other are one run: Ken,hello, world, again,5 under Name,Note,Amount gives the note hello, world, again. The space rule wants exactly one space followed by text, so Acme, Inc (two spaces) is not explained, and a single clean row with a value starting with a space turns the rule off for the whole file. Commas in different places would need two joins, which this code does not try. Only a single explained join becomes a suggestion. Two candidates mean the data cannot decide, and choosing one would be a guess.

Step 5: sort every row into imported or "needs a look"

checkCsv puts it together. It skips blank lines and removes a byte order mark at the start of the text.

headerIndex counts records after blank lines are removed, not physical lines. If your header detection (see detecting the header row) returns a line number, convert it first.

A row with empty values at the end is treated as "trailing delimiters" only when the rest of it fits; otherwise it goes through the join search like any other row with too many values:

const QUOTE_PROBLEMS = {
  "stray-quote": "a quote mark inside a value that does not start with one",
  "text-after-quote": "text after the closing quote of a value",
};

// Splits a file into rows you can import and issues a person must look at.
// A row with a problem is never in `rows`; a suggestion waits for a yes.
function checkCsv(text, { delimiter = ",", headerIndex = 0 } = {}) {
  const records = parseRecords(text.replace(/^\uFEFF/, ""), delimiter)
    .filter((r) => !isBlank(r));
  const header = records[headerIndex];
  if (!header) return { header: [], rows: [], issues: [] };
  const width = header.fields.length;
  const body = records.slice(headerIndex + 1);
  const good = body.filter((r) => r.fields.length === width && !r.problems.length);
  const kinds = columnKinds(good, width);
  // If the file writes "a, b, c", a leading space explains nothing.
  const spacedFile = good.some((r) => r.fields.slice(1).some((f) => f.startsWith(" ")));
  const rows = [], issues = [];
  const values = (n) => `${n} ${n === 1 ? "value" : "values"}`;
  const report = (r, kind, message, suggestion = null) => issues.push({
    line: r.line, kind, message: `Line ${r.line}: ${message}`, fields: r.fields, suggestion,
  });

  body.forEach((r, index) => {
    const count = r.fields.length;
    if (r.problems.includes("unclosed-quote")) {
      report(r, "unclosed-quote", `a quote opens on line ${r.quoteLine} and never ` +
        `closes, so lines ${r.quoteLine} to ${r.lastLine} became one value.`);
    } else if (r.problems.length) {
      const what = r.problems.map((p) => QUOTE_PROBLEMS[p]).join(" and ");
      report(r, r.problems[0], `${what}. Check that it reads correctly.`,
        count === width ? r.fields : null);
    } else if (count === width) {
      rows.push(r);
    } else if (count > width) {
      const kept = r.fields.slice(0, width);
      if (r.fields.slice(width).every((f) => !f.trim()) && fits(kept, kinds)) {
        report(r, "trailing-delimiter", `${values(count - width)} after the last column, ` +
          "all empty.", kept);
        return;
      }
      const joins = findJoins(r.fields, width, kinds, delimiter, spacedFile);
      const why = joins.length === 1
        ? `${JSON.stringify(joins[0].result[joins[0].at])} as one value fits the other rows.`
        : joins.length ? `${joins.length} different joins would fit, so none is suggested.`
        : "No single join fits the other rows.";
      report(r, "too-many", `${values(count)}, the header has ${width}. ${why}`,
        joins.length === 1 ? joins[0].result : null);
    } else {
      const next = body[index + 1];
      const hint = next && count + next.fields.length - 1 === width
        ? " With the next line it would fit: a line break inside a value?" : "";
      report(r, "too-few", `${values(count)}, the header has ${width}.${hint}`);
    }
  });
  return { header: header.fields, rows, issues };
}

Each issue carries a message ready to show, such as Line 5: 5 values, the header has 4. "Acme, Inc" as one value fits the other rows. For a row with too few values, the message adds a hint when this line and the next together have the right count, which is what an unquoted line break inside a value looks like. That case gets no suggestion: a row that is simply missing a value looks the same, and the hint can also appear when the next line is a short row of its own.

Empty values after the last column (15,,) are common in exports and lose nothing when dropped, but they are only dropped if the remaining values fit the columns. Bo Chen,Lyon,15,, in the same file is reported as too many values with no suggestion, because 15 would land in City: that row is missing its company. Ken Mori,Acme, Inc,Osaka, (Amount left blank) gets the Acme, Inc join.

An unclosed quote is the one problem that hides other rows. In a file whose lines 2 to 5 are Yui,Acme,49 / Ken,"Mori Ltd,120 / Li,Orbit,7 / Bo,Chen,9, everything from line 3 on becomes one value, so only Yui's row is imported and the message reads Line 3: a quote opens on line 3 and never closes, so lines 3 to 5 became one value. The user has to fix the file; any automatic recovery would be a guess about where the value was meant to end.

Step 6: let the user confirm

importCsv connects the parts to your interface. confirm is a function you supply: show the message and the suggested row, return true if the user accepts.

// confirm(issue) is your UI: show issue.message and issue.suggestion,
// return true if the user accepts the suggestion.
function importCsv(text, confirm) {
  const guess = guessDelimiter(text);
  const { header, rows, issues } = checkCsv(text, { delimiter: guess.delimiter });
  const accepted = rows.map((r) => ({ line: r.line, fields: r.fields }));
  const open = [];
  for (const issue of issues) {
    if (issue.suggestion && confirm(issue)) {
      accepted.push({ line: issue.line, fields: issue.suggestion });
    } else {
      open.push(issue);
    }
  }
  accepted.sort((a, b) => a.line - b.line);
  return { header, rows: accepted, open, delimiter: guess.delimiter, delimiterSure: guess.sure };
}

Check delimiterSure before anything else: if it is false, ask the user to pick the delimiter and run checkCsv with their choice, without showing the row issues from the guess. Accepted rows go back in file order, so line numbers in later messages still match. Everything left in open needs the user to edit the file or skip the row; list those by line number and let them download the list. A wrong delimiter makes every row look broken, which is why the delimiter comes first.

A repaired value is still text: 1,234 needs its separator removed before Number(), which returns NaN for it. Parsing numbers, including decimal commas, is covered in parsing European number formats.

If you already use a CSV library, you do not have to replace it. Run checkCsv on the same text when the library reports rows with the wrong number of fields, and import the rows it accepts plus the suggestions your user confirms.

What this does not cover

  • A broken header row. The header sets the number of columns, so an unquoted comma in it, or a delimiter at its end, makes every row look wrong. If most rows have one value more or fewer than the header, check the header first.
  • Two separate unquoted commas in one row. Only one run of neighbouring values is joined, so such rows are flagged without a suggestion.
  • Files written as a, b, c without quotes get flags only (and grouped-number joins), since the space rule is off for them.
  • A first line such as sep=; that names the delimiter. If your files can have one, remove it before calling checkCsv, or it becomes the header.
  • Kinds beyond plain numbers. $49, 12.5% and dates are treated as text. Extend NUMBER or add kinds for the formats your columns hold.
  • Files where few rows are clean. With fewer than two clean values in a column, its kind is "any" and only the space rule can explain a join.
  • Repairing line breaks inside unquoted values: you get a hint, not a fix.
  • Very large files. The whole text is parsed in memory, which is fine for typical uploads.
  • Decoding and header detection, which come before this. See reading Shift_JIS, Windows-1252 and UTF-16 files and detecting the header row.
