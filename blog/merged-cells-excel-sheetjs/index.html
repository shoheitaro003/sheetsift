Handle merged cells in Excel imports with SheetJS

2026-11-21

A customer uploads a sales report. "North" is merged over two rows, "Q1" over two columns, and the header takes two rows. Your importer reads it with sheet_to_json and gets columns called __EMPTY, a first record that is really the second header row, and a row where the region is empty.

By the end of this post you will have readMergedTable(bytes): five functions plus a few one-line helpers, on top of SheetJS. It turns a two-row header into one name per column (Q1 Revenue), copies merged text labels down their column, skips title rows, and reports with Excel addresses the merges it should not guess about. Every function and every result quoted below is checked by our test file in Node 22 with SheetJS 0.20.3.

What SheetJS gives you

When you merge cells in Excel, "the contents of only one cell (the upper-left cell for left-to-right languages, or the upper-right cell for right-to-left languages) appear in the merged cell", and "the contents of the other cells that you merge are deleted" (Microsoft Support, "Merge and unmerge cells in Excel", read 2026-11-20). The file stores the value in one cell and the merge as a separate list of ranges.

Here is the report from the introduction, read the usual way:

// Sales.xlsx, six merges: "Region" over A1:A2, "Rep" over B1:B2, "Q1" over C1:D1,
// "Q2" over E1:F1, "North" over A3:A4, "Note: figures in EUR" over A6:F6.
const sheet = workbook.Sheets[workbook.SheetNames[0]];
const records = XLSX.utils.sheet_to_json(sheet, { defval: "" });
Object.keys(records[0]); // [ 'Region', 'Rep', 'Q1', '__EMPTY', 'Q2', '__EMPTY_1' ]
records[0].Q1;           // 'Revenue'  (the second header row, read as data)
records[2].Region;       // ''         (Bo's row: "North" is only in A3)
sheet["!merges"].length; // 6

Three things go wrong. Columns under a group label have no name, so SheetJS calls them __EMPTY and __EMPTY_1. The second header row comes back as a record. And every row covered by a merge, except the first, is empty in the merged column.

The merges are all there in sheet["!merges"]; the code below uses them.

Step 1: read the rows and the merges

The code in steps 1 to 4 goes in one module: the small helpers at the top of step 2 are used by the later steps too.

// npm install https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz
import * as XLSX from "xlsx";

// rows: arrays of cells from the first sheet. merges: the sheet's merged ranges.
// Both count from 0 at the top-left cell of the sheet's stored range (origin).
function readSheet(bytes) {
  const data = bytes instanceof ArrayBuffer ? new Uint8Array(bytes) : bytes;
  const starts = (a, b) => data[0] === a && data[1] === b;
  // .xlsx files are zip archives (they start with "PK"); .xls files start with D0 CF.
  // Anything else is text. Decode it yourself: without a byte order mark (BOM),
  // SheetJS does not assume UTF-8, and "München" would arrive as "MÃ¼nchen".
  // FF FE and FE FF are UTF-16 BOMs, as in Excel's "Unicode Text" export.
  const binary = starts(0x50, 0x4b) || starts(0xd0, 0xcf);
  const encoding = starts(0xff, 0xfe) ? "utf-16le" : starts(0xfe, 0xff) ? "utf-16be" : "utf-8";
  const workbook = binary
    ? XLSX.read(data, { raw: true })
    : XLSX.read(new TextDecoder(encoding, { fatal: true }).decode(data), { type: "string", raw: true });
  const sheet = workbook.Sheets[workbook.SheetNames[0]];
  if (!sheet || !sheet["!ref"]) return { rows: [], merges: [], origin: { r: 0, c: 0 } };
  const origin = XLSX.utils.decode_range(sheet["!ref"]).s;
  const rows = XLSX.utils.sheet_to_json(sheet, {
    header: 1, defval: "", blankrows: true, raw: true });
  const merges = (sheet["!merges"] ?? []).map((m) => ({
    address: XLSX.utils.encode_range(m), // "C1:D1", for messages
    top: m.s.r - origin.r, bottom: m.e.r - origin.r,
    left: m.s.c - origin.c, right: m.e.c - origin.c,
  }));
  return { rows, merges, origin };
}

header: 1 returns each row as an array, so you decide what the column names are. defval: "" fills missing cells and blankrows: true keeps empty rows, so rows[r][c] always points at the same cell as the sheet.

A CSV file is text, and SheetJS has to guess its encoding. In our test, a UTF-8 CSV without a byte order mark (BOM, three bytes some programs put at the start of UTF-8 files) comes back as MÃ¼nchen instead of München. So readSheet decodes text files itself: as UTF-16 when the file starts with a UTF-16 BOM (Excel's "Unicode Text" export does), and as UTF-8 otherwise. With fatal: true, a file in another encoding, such as a Windows-1252 export, throws a TypeError instead of filling your database with wrong characters; our post on decoding legacy CSV files shows how to read those.

The stored range is the block of cells the file says it uses, in sheet["!ref"], such as A1:F6. It does not have to start at A1. origin is its first cell, and each merge is moved by it so it uses the same positions as rows. The original address is kept, because that is what the user sees in Excel. raw: true keeps CSV text as text, so 0123 is not turned into 123.

Step 2: find the header rows and name the columns

The header has more than one row when a merge in it says so. A label merged down, like Region over rows 1 and 2, covers the row below. A label merged across, like Q1 over C and D, names a group, so the row below holds the real column names.

const isEmpty = (value) => String(value ?? "").trim() === "";
const isLabel = (value) => typeof value === "string" && value.trim() !== "";
const covers = (m, r, c) => r >= m.top && r <= m.bottom && c >= m.left && c <= m.right;
// What the user sees in a cell: a cell under a merge shows the merge's value.
const shown = (rows, merges, r, c) => {
  const m = merges.find((range) => covers(range, r, c));
  return m ? rows[m.top]?.[m.left] : rows[r]?.[c];
};

// A row can be part of the header only if it has labels and no numbers, dates or booleans.
const labelRow = (row = []) => row.some(isLabel) && row.every((v) => isEmpty(v) || isLabel(v));

// How many rows the header has, starting at row `top`. A label merged down ("Region"
// over two rows) covers the rows below it. A label merged across ("Q1" over two
// columns) names a group, so the row below belongs to the header if it has a label
// under every column of the group. maxDepth keeps a stray merge from eating the data.
function headerDepth(rows, merges, top, maxDepth = 3) {
  let bottom = top;
  for (let changed = true; changed; ) {
    changed = false;
    for (const m of merges) {
      if (m.top < top || m.top > bottom) continue;
      // last: the lowest row this merge pulls into the header.
      let last = m.bottom;
      const below = [];
      for (let c = m.left; c <= m.right; c++) below.push(shown(rows, merges, m.bottom + 1, c));
      if (m.right > m.left && below.every(isLabel)) last = m.bottom + 1;
      if (last <= bottom || last >= top + maxDepth) continue;
      if (!rows.slice(bottom + 1, last + 1).every((row) => labelRow(row))) continue;
      bottom = last;
      changed = true;
    }
  }
  return bottom - top + 1;
}

// One name per column: "Q1" above "Revenue" becomes "Q1 Revenue".
// A merged cell gives its value to every column it covers, once per column.
function headerNames(rows, merges, top, depth) {
  const width = Math.max(0, ...rows.slice(top, top + depth).map((row) => row.length));
  const names = [];
  for (let c = 0; c < width; c++) {
    const parts = [];
    let previous = null;
    for (let r = top; r < top + depth; r++) {
      const m = merges.find((range) => covers(range, r, c)) ?? null;
      if (m && m === previous) continue; // a label merged down counts once
      previous = m;
      const value = m ? rows[m.top]?.[m.left] : rows[r]?.[c];
      if (!isEmpty(value)) parts.push(String(value).trim());
    }
    names.push(parts.join(" "));
  }
  return names;
}

Why each rule is there:

  • A header row holds only text. A row with a number, a date or a boolean is data, so a merged header over data columns cannot swallow the first record. (With raw: true, dates in an .xlsx file arrive as serial numbers; our post on reading Excel dates shows how to convert them.)
  • A group needs a label under every column it covers. Q1 over Revenue and an empty cell is not a two-row header. A cell under another merge counts as that merge's label, so 2026 over a merged Q1 and a merged Q2 works.
  • The loop repeats because one extra row can bring in another: 2026 over Q1 and Q2, each over Rev and Cost, gives names like 2026 Q1 Rev.
  • maxDepth is 3 because a label merged down over many rows is more likely a layout choice than a header. Such a merge is reported in step 3.
  • A merge counts once per column. Region merged over two rows gives Region, not Region Region.

Step 3: fill or flag the merges in the data

Below the header, the shape of a merge and the type of its value tell you what it means. Only one case is safe to fill: text merged down one column.

// Copies each merged value down its column; reports the merges it will not fill.
// Changes rows in place. firstData: index of the first row under the header.
// width: number of named columns in the table.
function fillMerges(rows, merges, firstData, width, origin) {
  const notes = [];
  const problems = [];
  const titleRows = new Set();
  const address = (r1, c1, r2, c2) => XLSX.utils.encode_range({
    s: { r: origin.r + r1, c: origin.c + c1 }, e: { r: origin.r + r2, c: origin.c + c2 } });
  for (const m of merges) {
    if (m.bottom < firstData) continue; // inside the header: headerNames used it
    if (m.top >= rows.length) continue;  // below the last row: nothing to read
    if (m.top < firstData) {
      problems.push({ range: m.address, reason: "runs from the header into the data" });
      continue;
    }
    const value = rows[m.top]?.[m.left] ?? "";
    const last = Math.min(m.bottom, rows.length - 1);
    // Excel shows only the first cell of a merge. A value stored under it is invisible
    // to the user, so it is reported and not imported.
    for (let r = m.top; r <= last; r++) {
      for (let c = m.left; c <= m.right; c++) {
        if ((r === m.top && c === m.left) || isEmpty(rows[r][c])) continue;
        problems.push({ range: m.address, reason: `hides ${JSON.stringify(rows[r][c])} in ${address(r, c, r, c)}` });
        rows[r][c] = "";
      }
    }
    const height = m.bottom - m.top + 1;
    const span = m.right - m.left + 1;
    const first = address(m.top, m.left, m.top, m.left);
    if (span === 1 && isLabel(value)) {
      // One column, several rows, with text: a group label such as a region. Fill it down,
      // except into rows that are empty in the file: those are skipped later.
      const filled = [];
      for (let r = m.top + 1; r <= last; r++) {
        if (rows[r].every(isEmpty)) continue;
        rows[r][m.left] = value;
        filled.push(address(r, m.left, r, m.left));
      }
      if (filled.length > 0) {
        notes.push({ range: m.address, reason: `${JSON.stringify(value)} copied into ${filled.join(", ")}` });
      }
    } else if (span === 1) {
      // A number, date or boolean merged down: copying 100 into two invoice lines
      // would double it. Empty merges need nothing.
      if (!isEmpty(value) && last > m.top) {
        problems.push({ range: m.address, reason: `covers ${height} rows; its value ${JSON.stringify(value)} is read into ${first} only` });
      }
    } else if (m.left <= 0 && m.right >= width - 1) {
      // One cell across the whole table: a title or a note, not a record.
      for (let r = m.top; r <= last; r++) titleRows.add(r);
      const row = origin.r + m.top + 1;
      const where = last > m.top ? `rows ${row}-${origin.r + last + 1}` : `row ${row}`;
      // Text is a title or a footnote. A number across the table (a total?) is reported.
      const list = isLabel(value) || isEmpty(value) ? notes : problems;
      list.push({ range: m.address, reason: `${where} skipped: ${JSON.stringify(value)} spans the table` });
    } else {
      // Across columns: the value belongs to one of them, and only the user knows which.
      const size = height > 1 ? `${height} rows and ${span} columns` : `${span} columns`;
      problems.push({ range: m.address, reason: `covers ${size}; its value is read into ${first} only` });
    }
  }
  return { notes, problems, titleRows };
}

Two fills would change your numbers. An invoice total of 100 merged over two invoice lines, copied down, becomes 200 when you add up the lines. A note merged over C and D, copied across, would also land in D, which may be your amount column. In both cases the value stays in the cell where the file stores it, and the user decides. Dates count as numbers here, because with raw: true an .xlsx date arrives as a serial number; if a date column is grouped on purpose, fill it with fillDown from the CSV section below.

Excel deletes the other cells' contents when you merge, but a file written by another program can still hold values under a merge. Our test writes one with SheetJS: North merged over A2:A3, with South stored in A3. The user only sees North, so fillMerges reports the hidden value and does not import it, for every shape of merge.

"The whole table width" means from the first column to the last column that has a name. A stray cell further right, such as a comment in column H, does not stop a footnote row from being recognised. A merge that starts below the last row of the sheet is ignored: it has no value to read.

Step 4: read the table

readMergedTable puts the steps together and returns one record per data row, with the row number the user sees in Excel.

// headerTop: index of the first header row in rows (0, or what your header detection found).
function readMergedTable(bytes, headerTop = 0) {
  const { rows, merges, origin } = readSheet(bytes);
  if (rows.length <= headerTop) {
    const problems = [{ range: null, reason: "the sheet has no header row" }];
    return { columns: [], records: [], notes: [], problems };
  }
  const depth = headerDepth(rows, merges, headerTop);
  const columns = headerNames(rows, merges, headerTop, depth);
  const firstData = headerTop + depth;
  // The table ends at the last named column; a stray cell further right does not widen it.
  const width = columns.findLastIndex((name) => name !== "") + 1;
  if (width === 0) {
    const cell = XLSX.utils.encode_cell({ r: origin.r + headerTop, c: origin.c });
    const reason = `row ${origin.r + headerTop + 1} has no column names; if the header is lower, pass its index as headerTop`;
    return { columns: [], records: [], notes: [], problems: [{ range: cell, reason }] };
  }
  // Rows that are empty in the file are skipped.
  const blank = new Set(rows.flatMap((row, r) => (row.every(isEmpty) ? [r] : [])));
  const { notes, problems, titleRows } = fillMerges(rows, merges, firstData, width, origin);
  if (depth > 1) {
    const range = XLSX.utils.encode_range({
      s: { r: origin.r + headerTop, c: origin.c },
      e: { r: origin.r + firstData - 1, c: origin.c + Math.max(width, 1) - 1 },
    });
    notes.unshift({ range, reason: `${depth} header rows combined into one name per column` });
    // Was a lower header row really the first record? Two signs, both reported:
    // a value under a header cell that is not merged ("Ana" under "Name"; in a real
    // header that cell is empty), or a first data row with text in the same columns.
    const next = rows.slice(firstData).find((row) => !row.every(isEmpty)) ?? [];
    for (let r = headerTop + 1; r < firstData; r++) {
      const row = origin.r + r + 1;
      const used = rows[r].flatMap((value, c) => (isEmpty(value) ? [] : [c]));
      const loose = used.filter((c) =>
        !merges.some((m) => m.top >= headerTop && m.top < r && covers(m, m.top, c)));
      for (const c of loose) {
        const cell = XLSX.utils.encode_cell({ r: origin.r + r, c: origin.c + c });
        problems.push({ range: cell, reason: `${JSON.stringify(rows[r][c])} is under a header cell that is not merged; row ${row} may be data` });
      }
      if (loose.length === 0 && used.length > 0 && used.every((c) => isLabel(next[c]))) {
        const rowRange = XLSX.utils.encode_range({
          s: { r: origin.r + r, c: origin.c }, e: { r: origin.r + r, c: origin.c + width - 1 } });
        problems.push({ range: rowRange, reason: `row ${row} was read as a header row, but the first data row has text in the same columns; check whether row ${row} is data` });
      }
    }
  }

  const isData = (r) => r >= firstData && !titleRows.has(r) && !blank.has(r);
  // A repeated name gets a number ("Amount (2)"), so its values are not overwritten
  // in the records. "Email" and "EMAIL" count as the same name.
  const used = new Set(columns.map((name) => name.toLowerCase()));
  const seen = new Set();
  columns.forEach((name, c) => {
    const cell = XLSX.utils.encode_cell({ r: origin.r + headerTop, c: origin.c + c });
    if (name === "") {
      const hasData = rows.some((row, r) => isData(r) && !isEmpty(row[c]));
      if (hasData) problems.push({ range: cell, reason: "has data but no column name" });
      return;
    }
    if (seen.has(name.toLowerCase())) {
      let n = 2;
      while (used.has(`${name} (${n})`.toLowerCase())) n++;
      columns[c] = `${name} (${n})`;
      used.add(columns[c].toLowerCase());
      problems.push({ range: cell, reason: `repeats the column name ${JSON.stringify(name)}; read as ${JSON.stringify(columns[c])}` });
    }
    seen.add(columns[c].toLowerCase());
  });

  const records = [];
  rows.forEach((row, r) => {
    if (!isData(r)) return;
    // fromEntries defines own properties, so a column named "__proto__" is safe.
    const values = Object.fromEntries(
      columns.flatMap((name, c) => (name ? [[name, row[c] ?? ""]] : [])));
    records.push({ row: origin.r + r + 1, values }); // the row number the user sees in Excel
  });
  return { columns, records, notes, problems };
}

Besides the merges, it reports header problems that merges often cause. The first is a lower header row that may be the first record: a value under a header cell that is not merged, such as Ana under Name (in a real two-row header that cell is empty), or a first data row with text in the same columns. The other two are a column with data but no name, and a name used twice. Names that differ only in capital letters, like Email and EMAIL, count as the same name. The second one is renamed Amount (2), so both values show up in the preview instead of one overwriting the other. A column with neither a name nor data is dropped without a message.

Use records for the preview, and import only when problems is empty or the user has fixed or accepted each one. If the first row of the stored range has no names at all, as in an empty file or a sheet with blank rows above the table, you get one problem that says so: pass headerTop, as shown below.

Rows that are empty in the file are skipped, even when a merge fills the merged column in them, so a blank line inside a region does not become a record.

const { columns, records, notes, problems } = readMergedTable(await file.arrayBuffer());

//             'Q2 Revenue': 95, 'Q2 Cost': 35 } }

// [ 'A1:F2: 2 header rows combined into one name per column',
//   'A3:A4: "North" copied into A4',
//   'A6:F6: row 6 skipped: "Note: figures in EUR" spans the table' ]

Show the notes in your import preview, so the user can see that North was copied and row 6 was skipped. Show the problems and let the user fix the file, or confirm, before you import.

If the header is not in the first row, pass its index as headerTop: our post on finding the header row finds it. A title merged across the top, such as Sales export in A1:B1, is above the header and is ignored. To match the combined names to your own fields, use column mapping; it also reports required fields that no column fills.

CSV files have no merges

A CSV stores no merges. In our test, SheetJS returns no merges for a CSV, and a region merged over several rows arrives as one value followed by empty cells, the same as cells nobody filled in. You cannot tell the two apart from the file, so do not fill down on your own. If the user says a column is grouped this way, fill that column:

// A CSV keeps no merges: "North" merged over three rows arrives as "North", "", "".
// Fill a column only after the user says it is grouped this way, and after
// title and footnote rows are removed: in a CSV they arrive as records.
function fillDown(records, column) {
  let last = "";
  for (const record of records) {
    if (isEmpty(record.values[column])) record.values[column] = last;
    else last = record.values[column];
  }
  return records;
}

Use it after readMergedTable, which reads CSV files too. Three differences from .xlsx:

  • Every value in a CSV arrives as a string ("90", not 90), so convert numbers and dates in your own checks.
  • Title and footnote rows arrive as records. In our test, Note: figures in EUR becomes a record whose Region is the note, with no note or problem. Remove such rows before fillDown, or the note is copied into the rows below it.
  • If a file has sections, run fillDown on each section's records separately; otherwise a region carries over into the next section. The first rows stay empty if the column starts empty.

What this does not cover

  • Two-row headers in a CSV. Without merges you cannot see where Q1 ends, so readMergedTable reads one header row. Combine the rows yourself after the user confirms.
  • Numbers in a header row. A header cell typed as a number, such as the year 2026 under a merged Revenue, makes that row data, because a header row holds only text here. You get the columns Revenue and Revenue (2) with a repeated-name problem, and the years as the first record. If your users' files do this, type the years as text or confirm the header with the user.
  • A header over text-only data. Contact merged over two columns, with an email and a phone number stored as text below it, looks like a two-row header, so the first record becomes column names. The same happens with a label merged down: Name merged over A1:A2, with City in B1 and Berlin in B2, gives the column City Berlin. The code cannot be sure, so it reports a problem in two cases: a value sits under a header cell that is not merged, or the first data row has text in the same columns as the lower header row. The second check also flags some real headers over text-only data; the user confirms those. Without either sign, a lower header row is accepted.
  • A title merged down into the header. A merge that starts above headerTop and ends inside the header is not counted as a header row, but its value still becomes part of a column name. Pass the row under it as headerTop, or unmerge it.
  • Section labels as data. A row like Europe across the table is skipped. If the rows below belong to it, add it as a column yourself.
  • Other sheets and hidden rows. Only the first sheet is read, and this code does not check whether a row is hidden.
  • Blank cells that are not merged. They stay empty. Our post on placeholder values shows how to report them in required columns.
