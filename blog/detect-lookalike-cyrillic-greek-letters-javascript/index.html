Detect lookalike Cyrillic and Greek letters in JavaScript

2026-11-22

A customer imports a file, and one row has the email bo@exаmple.com. It looks like bo@example.com, but the second a is the Cyrillic letter U+0430. The lookup fails, the duplicate check misses it, and nothing on the screen shows why.

By the end of this post you will have checkId(value), which flags every character that is not ASCII in emails, SKUs and other IDs, and checkText(text), which flags names and other text that mix scripts, such as Latin and Cyrillic. Both put the suspect characters in square brackets and name their code and script, so your import preview can show them. The script rules follow Unicode's own definition of mixed-script text. Every function and every result quoted below is checked by our test file in Node 22.

Why equality, lowercase and NFKC miss it

const typed = "paypal";
const imported = "p\u0430yp\u0430l"; // both a's are CYRILLIC SMALL LETTER A (U+0430)

imported === typed;                   // false
imported.toLowerCase() === typed;     // false
imported.normalize("NFKC") === typed; // false: NFKC does not touch it
/^[\x20-\x7E]+$/.test(imported);      // false: an ASCII-only rule does catch it

The Cyrillic а is not a hidden or decorated form of the Latin a. It is a different letter that looks the same, so no normalization turns one into the other. NFKC, Unicode's compatibility normalization, maps full-width and other variant forms to their plain letters, but not one alphabet to another. Unicode's security standard, UTS #39, uses this very case as its example: "paypal" and "pаypаl", where the second word has U+0430 (UTS #39, section 4).

Every Unicode character has a script property: Latin, Cyrillic, Greek, Han and so on. A lookalike from another script shows up either as text that mixes scripts, or as an ID that is not ASCII, and both can be checked with regular expressions.

Step 1: find which scripts a value belongs to

A regular expression with the u flag can test a character's script with \p{Script=Cyrillic}. Some characters are used in several scripts, and Script only matches the main one. Script_Extensions matches all of them (MDN, Unicode character class escape, last modified 2026-11-06). For example, the Japanese long vowel mark ー has the script Common, but its script extensions are Hiragana and Katakana, which is what we want when checking a Japanese name.

// Scripts to tell apart. A letter in a script that is not listed counts as "Other".
const SCRIPTS = ["Latin", "Greek", "Cyrillic", "Armenian", "Georgian", "Cherokee", "Hebrew",
  "Arabic", "Devanagari", "Thai", "Han", "Hiragana", "Katakana", "Hangul", "Bopomofo"];
const SCRIPT_TESTS = SCRIPTS.map((name) =>
  [name, new RegExp(`\\p{Script_Extensions=${name}}`, "u")]);

// Writing systems that mix scripts on purpose (UTS #39 calls them Hanb, Jpan and Kore).
const WRITING_SYSTEMS = {
  Han: ["Han with Bopomofo", "Japanese", "Korean"],
  Hiragana: ["Japanese"],
  Katakana: ["Japanese"],
  Hangul: ["Korean"],
  Bopomofo: ["Han with Bopomofo"],
};

// Most digits, punctuation, spaces, emoji and combining marks belong to every script.
const ANY_SCRIPT = /[\p{Script_Extensions=Common}\p{Script_Extensions=Inherited}]/u;

// The scripts one character can belong to, or null for "any script".
// Cached, because a regular expression per script is slow on large files.
const scriptCache = new Map();
function scriptsOf(char) {
  if (!scriptCache.has(char)) scriptCache.set(char, findScripts(char));
  return scriptCache.get(char);
}
function findScripts(char) {
  if (ANY_SCRIPT.test(char)) return null;
  const found = SCRIPT_TESTS.filter(([, test]) => test.test(char)).map(([name]) => name);
  if (found.length === 0) return ["Other"];
  return [...found, ...new Set(found.flatMap((name) => WRITING_SYSTEMS[name] ?? []))];
}

// The scripts that every character in text can belong to.
// null: no letters at all. []: the text mixes scripts.
function resolvedScripts(text) {
  let common = null;
  for (const char of text) {
    const scripts = scriptsOf(char);
    if (scripts === null) continue;
    common = common === null ? scripts : common.filter((name) => scripts.includes(name));
  }
  return common;
}

The rules come from UTS #39, section 5.1, which calls a string mixed-script when no script is shared by all its characters:

  • Characters in Common or Inherited count as any script. Most digits, punctuation, spaces and emoji are Common, so Circ1e is still Latin. Digits that belong to one script count as that script: the Arabic-Indic ٠ (U+0660) makes abc٠ mixed.
  • Japanese, Korean and Chinese mix scripts on purpose. A Japanese name can hold Han, Hiragana and Katakana. UTS #39 adds a writing system to each such character's set (Japanese to Han, Hiragana and Katakana, for example), so ねガ resolves to Japanese and is not mixed.
  • The resolved scripts are the ones every character shares. resolvedScripts returns an empty list for mixed text and null for text with no letters at all, such as 123-45.

The rules are quoted from revision 31 of UTS #39 (the draft for Unicode 17, dated 2025-08-12, read 2026-11-22). They are unchanged since revision 25 (2022).

Only the 15 scripts in SCRIPTS are told apart. A letter from any other script, such as the Lisu letter ꓮ (U+A4EE), counts as "Other", which still makes text mixed when it stands next to Latin letters: ꓮpple is flagged. Add the scripts your users write.

Step 2: check IDs and text differently

An email, SKU or customer number is compared by your code, not read by people, so it can follow the strictest rule: every character must be ASCII. UTS #39 calls this level "ASCII-Only" (section 5.2). Names, company names and notes are read by people and can be in any script, so they only get the mixed-script check.

const codeOf = (char) =>
  "U+" + char.codePointAt(0).toString(16).toUpperCase().padStart(4, "0");
const SYSTEM_NAMES = new Set(Object.values(WRITING_SYSTEMS).flat());
// "U+0430 Cyrillic", for messages: scripts only, not the writing systems.
function label(char) {
  if (/\p{M}/u.test(char)) return `${codeOf(char)} combining mark`;
  const scripts = scriptsOf(char)?.filter((name) => !SYSTEM_NAMES.has(name)) ?? ["Common"];
  return `${codeOf(char)} ${scripts.join("/")}`;
}
// Puts square brackets around the characters isOdd picks out.
function describe(chars, isOdd) {
  const marked = chars.map((char) => (isOdd(char) ? `[${char}]` : char)).join("");
  return { marked, odd: [...new Set(chars.filter(isOdd).map(label))] };
}

// UTS #39 "Highly Restrictive" also allows Latin with Japanese, Korean or Chinese.
const WITH_LATIN = ["Japanese", "Korean", "Han with Bopomofo"];
function isMixed(text) {
  const scripts = resolvedScripts(text);
  if (scripts === null || scripts.length > 0) return false;
  const rest = [...text].filter((char) => !scriptsOf(char)?.includes("Latin")).join("");
  return !resolvedScripts(rest)?.some((name) => WITH_LATIN.includes(name));
}

// Names and other text: null, or the characters that are not in the main script.
// preferred: the script your users write. It is the main one whenever the text uses it.
function checkText(text, preferred = "Latin") {
  const chars = [...String(text ?? "")];
  if (!isMixed(chars.join(""))) return null;
  const counts = new Map();
  for (const char of chars) {
    for (const name of scriptsOf(char) ?? []) counts.set(name, (counts.get(name) ?? 0) + 1);
  }
  const top = Math.max(...counts.values());
  const main = counts.has(preferred) ? preferred : [...counts].find(([, n]) => n === top)[0];
  // Next to Latin, the Japanese, Korean or Chinese part most characters share is allowed.
  const partner = main === "Latin"
    ? WITH_LATIN.filter((name) => counts.has(name)).sort((a, b) => counts.get(b) - counts.get(a))[0]
    : undefined;
  const isOdd = (char) => {
    const scripts = scriptsOf(char);
    return scripts !== null && !scripts.includes(main) && !scripts.includes(partner);
  };
  return { main, ...describe(chars, isOdd) };
}

// IDs such as emails, SKUs and customer numbers: null, or the characters that are not ASCII.
function checkId(value) {
  const chars = [...String(value ?? "")];
  const isOdd = (char) => char.codePointAt(0) > 0x7f;
  return chars.some(isOdd) ? describe(chars, isOdd) : null;
}

Three choices in checkText, and why:

  • It checks the whole value, not word by word. A lookalike is often a single letter, such as the initial in Ј. Smith (Cyrillic U+0408) or the Я in Toys-Я-Us, and a one-letter word is never mixed on its own. The cost is that a name written in two alphabets, such as Анна Petrova, is flagged too, so treat text results as warnings the user can dismiss.
  • Latin next to Japanese, Korean or Chinese is allowed. Product names such as Tシャツ (T-shirt) mix them all the time, and UTS #39's "Highly Restrictive" level allows it (section 5.2). A lookalike added to such text is still marked: Tシャツа gives Tシャツ[а].
  • The script your users write is the main one. preferred defaults to Latin, so in ΑΒC-123 the two Greek capitals are marked, not the Latin C. If the text has no character in preferred, the script most characters belong to is the main one. Pass "Cyrillic" if that is what your users write. The cost: when the one wrong letter is in your preferred script, everything else is marked instead. Mосква with a Latin M is flagged, but the five Cyrillic letters are marked, not the M.

The brackets matter because a marked character still looks like the one it imitates. The code and script after it, such as U+0430 Cyrillic, tell the user which letter to retype. "Common" means a character shared by all scripts, such as the en dash in AB–12, and "Other" a script that is not in SCRIPTS.

Step 3: report the problems by row

checkRecords runs checkId or checkText on each column, by the kind you set in COLUMN_KINDS, and returns one message per problem. Columns that are not listed are not checked.

const COLUMN_KINDS = { email: "id", sku: "id", name: "text", company: "text" };

// records: objects from your parser, after cleaning invisible characters. Each has
// rowNumber, the row in the file, so messages still point to the right row
// when the parser skips blank rows or the header is not on row 1.
function checkRecords(records, preferred = "Latin") {
  const warnings = [];
  for (const record of records) {
    for (const [column, kind] of Object.entries(COLUMN_KINDS)) {
      const found = kind === "id" ? checkId(record[column]) : checkText(record[column], preferred);
      if (!found) continue;
      const problem = kind === "id" ? "is not plain ASCII:" : `mixes ${found.main} with`;
      const where = `Row ${record.rowNumber}, ${column}`;
      warnings.push(`${where}: "${found.marked}" ${problem} ${found.odd.join(", ")}.`);
    }
  }
  return warnings;
}

Here it is on three rows. The Cyrillic and Greek letters are written as escapes such as \u0430 so you can see them in the code; in a real file they are the letters themselves.

checkRecords([
  { rowNumber: 2, email: "ana@example.com", sku: "AB-123",
    name: "Ana Petrova", company: "Acme" },
  { rowNumber: 3, email: "bo@ex\u0430mple.com", sku: "AB-124",
    name: "Bo Chen", company: "\u0410cme" },
  { rowNumber: 5, email: "chloe@example.com", sku: "\u039a\u039c-7",
    name: "Chlo\u00eb \u041c. Martin", company: "Zeta" },
]);
// [ 'Row 3, email: "bo@ex[а]mple.com" is not plain ASCII: U+0430 Cyrillic.',
//   'Row 3, company: "[А]cme" mixes Latin with U+0410 Cyrillic.',
//   'Row 5, sku: "[Κ][Μ]-7" is not plain ASCII: U+039A Greek, U+039C Greek.',
//   'Row 5, name: "Chloë [М]. Martin" mixes Latin with U+041C Cyrillic.' ]

What to do with the messages is your choice. We would block the import on an ID message until the user fixes or confirms the cell, and show text messages in the preview without blocking, since a mixed name is sometimes intended.

Run these checks after cleaning invisible characters and normalizing IDs with NFKC, as in our post on invisible characters. NFKC turns full-width letters such as ＡＢ into ASCII and joins an e and a combining accent (U+0301) into one é; it leaves the Cyrillic and Greek letters in the example unchanged.

What this does not cover

  • Whole words in another script. An all-Cyrillic word that looks like a Latin one, such as Сігсӏе, passes checkText. UTS #39 calls these whole-script confusables. Detecting them needs Unicode's confusables.txt data file, which maps each character to the one it can be mistaken for (section 4); this post does not include it. The same file would let you suggest a fix, such as "did you mean a?".
  • Lookalikes inside one script. l and I, 0 and O, or rn and m are all ASCII and all Latin. So are styled letters such as the mathematical bold 𝐀 in a text column; NFKC turns them into plain letters, so normalize text with NFKC before comparing it if that matters to you.
  • Control characters. checkId only looks for characters above U+007F, so a tab or NUL passes it. Remove those first, as the invisible characters post does.
  • Internationalized emails and domains. checkId flags anna@münchen.de because it is not ASCII. If you accept such addresses, let the user confirm the message instead of blocking.
  • Scripts not in the list. Letters from two scripts that are both "Other" are taken as one script. Add every script you expect to SCRIPTS.
  • Unicode versions. \p{Script_Extensions=...} uses the Unicode data built into the JavaScript engine (in Node, process.versions.unicode; our tests ran with 17.0). A new version can change the extensions of a few characters, so test with your users' samples after upgrading.
