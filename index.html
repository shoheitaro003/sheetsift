What it handles

The six problems behind most failed imports

Most importers assume a clean CSV with headers on row 1. SheetSift handles the common ways real files differ, and does nothing else.

A3

Header row is not row 1Title lines and blank rows above the table are detected and skipped.

A7

Totals rowsA “Total” row at the bottom is recognised and kept out of your database.

B3

Column names that don't match“E-mail”, “Email address” and “mail” all map to your email field automatically.

C4:C6

Mixed date formats2026/04/03, 03.04.2026 and Apr 3 2026 become one ISO date.

E5

Decimal commas49,00 and 1,234.56 are read correctly for the user's locale.

B6

Cell-level fixesUsers correct flagged cells in place before anything is submitted.

How it works

Three steps to a working import screen

Step 1

Install the component

One npm package. Works with any React app and your existing design tokens.

Step 2

Describe your columns

Field names, types, required fields and your own validation functions.

Step 3

Receive clean rows

A typed array of validated records, plus a report of what was skipped and why.

import { SheetSift } from "sheetsift"

<SheetSift
  fields={[
    { key: "name",  label: "Full name", required: true },
    { key: "email", type: "email" },
    { key: "signed_up_at", type: "date" },
    { key: "mrr",   type: "number" },
  ]}
  onComplete={(rows) => saveCustomers(rows)}  // runs in your app, on your servers
/>

Self-hosted by design

No per-import fees. No customer data in someone else's cloud.

Hosted import services usually charge by the import or by the month, and route your customers' files through their servers. SheetSift parses files in the browser and hands the result to your code.

  • Files are read in the user's browser and handed straight to your code.
  • Nothing is sent to SheetSift. No tracking, no account, no server to run.
  • Fits security reviews that rule out third-party data processors.
  • One annual license per company, not per import or per end user.
