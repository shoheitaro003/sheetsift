title: Read two-row Excel headers with merged cells in SheetJS description: SheetJS reads one header row, so "Q1" merged over Revenue and Cost gives __EMPTY keys. A tested function that names the columns "Q1 Revenue" instead. date: 2026-11-28 ---

A customer uploads a sales report whose header has two rows: "Q1" is merged across two columns, with "Revenue" and "Cost" under it. SheetJS uses only the first row as column names, so you get keys like __EMPTY, and the second header row arrives as a record.

By the end of this post you will have readTwoRowTable(sheet), one function that needs only SheetJS. It names the columns Q1 Revenue, Q1 Cost and so on, returns the records, and refuses a header it cannot name safely, with the Excel address of the cell to fix. Every result below is checked by our test file (the tests named th:) in Node 22 with SheetJS 0.20.3.

Two facts cause this. A merged range stores its value in its first (top-left) cell only, so D1 and F1 are empty. And sheet_to_json takes names from one row. The merges themselves are listed in sheet["!merges"], which is all you need to put "Q1" back over column D.

The function

What it does, and why:

  • Reads both header rows as text. It uses cell.w, the text Excel displays (or the stored value when a cell has no display text), so a date used as a group label reads "Jan 2026", not its serial number. Line breaks inside a header cell become one space.
  • Copies each merged label across its columns. "Q1" from C1 goes to D1 too. A label merged down, like "Region" over A1:A2, has nothing under it, so its name is just "Region". Merges above the header, in the data or beside the table are ignored here.
  • Checks that the header really has two rows: at least one group label must cover two columns that have names under them. It may be merged, or typed over each column ("Q1", "Q1"); both work.
  • Joins the two rows: "Q1" and "Revenue" become Q1 Revenue.
  • Reads the records with those names. Passing an array as header tells SheetJS the names, and range: s.r + 2 starts at the first row under the header. Empty rows are skipped, and defval: "" gives empty cells an empty string instead of a missing key. A null name makes SheetJS skip that column, which is how an empty column without a name is left out (a test checks this).

The sheet's stored range, sheet["!ref"], is the block of cells the file uses. The function treats its first two rows as the header, so it also works when the table starts at C3.

What it refuses

Guessing a column name wrong puts values in the wrong field without any error, so the function throws instead. Each case below is a test. One mistake can cause more than one line: a refused merge is not copied, so the "no group label" lines may follow it.

No group label over two named columnsrow 1: no group label covers two columns; is this a one-row header?With a one-row header, row 2 is data: "Name" and "Ana" would become one column name. A CSV with a one-row header lands here too.
A name in row 2 with nothing above it, next to grouped columnsD2: "Cost" has no group label above itThe group was probably meant to cover it but is not merged. Is it "Q1 Cost" or a column of its own? Only the user knows.
One label merged across the whole first rowA1:C1: spans the whole table; is it a title?That is usually a report title, not a group. Move the stored range below it (see the end of this post). A table whose one group really covers every column is refused too.
A merge cut by the edge of the stored rangeA1:B2: crosses the table's edgeIts label sits outside the range, so it would be lost. This happens after you move sheet["!ref"] into the middle of a merge.
A merge that starts in row 2B2:C2: merged in the second header rowThe header probably has three or more rows.
A merge from the header into the data, or from above into the headerA1:A3: reaches below the header, or A1:A3: starts above the header after you move the range to start at row 2Same: a deeper header, or a layout mistake.

Case is ignored because a mapping step that ignores case would mix up "Cost" and "cost". A label merged across and down (A1:B2) also lands here: it names two columns, and the code cannot tell which values belong to it.

The second row matters most in practice. If a group label is only centered over its columns with cell formatting, not merged, the file stores it in its first cell alone and lists no merge. Our test file has such a sheet, and the function reports:

{{code:TH_REFUSED}}

The fix for the user is to merge C1:D1 and E1:F1, or to type "Q1" in D1 and "Q2" in F1.

When this is not enough

  • Three or more header rows. They are refused, as above. To support them, repeat the copy-and-join step for each row, and check that every merge in the header stays inside it.
  • A title above the header. The function expects the header in the first two rows of the stored range. Our post on finding the header row shows how to locate it; then set sheet["!ref"] to start there (for example "A2:F6") before you call this function. A title merged above is then ignored.
  • Merged cells in the data. A region merged over two sales rows keeps its value in the first row only; the second gets an empty string. Our post on filling merged cells handles those.
  • Dates in the data. Header labels use the displayed text, but records hold stored values, so a date cell arrives as a serial number such as 46023. Our post on reading Excel dates converts them.
  • Which sheet. You pass the sheet, so the caller decides. The example uses the first one.
  • A one-row header with a repeated name. If row 1 is Name, Notes, Notes and row 2 is data, the check for a group passes, and the first data row becomes part of the names (Notes late, Notes paid). Call this function only for files you expect to have two header rows, and show the column names in your preview so the user can spot it.
  • Row numbers for error messages. Each record has a hidden (non-enumerable) __rowNum__ property, counted from 0, so the Excel row is record.__rowNum__ + 1. Our tests check this on SheetJS 0.20.3.
