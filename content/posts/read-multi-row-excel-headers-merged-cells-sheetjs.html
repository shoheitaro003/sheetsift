title: Read multi-row Excel headers with merged cells in SheetJS description: SheetJS reads one header row, so "Q1" merged over Revenue and Cost gives __EMPTY keys. Tested JavaScript that builds names like "Q1 Revenue" instead. date: 2026-11-25 ---

A customer uploads a sales report whose header has two rows: "Q1" is merged across two columns, with "Revenue" and "Cost" under it. SheetJS reads the first row as the column names, so you get keys like __EMPTY, and the second header row arrives as a record.

By the end of this post you will have readGroupedTable(bytes): it finds how many rows the header has from its merged cells, names each column from top to bottom (Q1 Revenue, Q1 Cost), and refuses headers it would name wrongly, with the Excel address of the cell to fix. It builds on readXlsx and fillMerges from our post on filling merged cells, which handles merges in the data rows. Every result quoted below is checked by our test file (the tests named mh:) in Node 22 with SheetJS 0.20.3.

A merged range stores its value in its first (top-left) cell only, so D1 and F1 are empty and SheetJS invents __EMPTY names for them. Starting at row 2 loses "Q1" and "Q2" instead, and the two Revenue columns become Revenue and Revenue_1. Neither tells your column mapping which quarter a number belongs to.

Step 1: read the header

The merges tell you the shape of the header. A label merged across columns is a group label: it says that the columns under it share a name, so the row under it must be part of the header too. A label merged down, like "Region" over A1:A2, just fills the header's height and counts once in the name. A merge with no value is layout, and is ignored.

What the three parts do, and why:

  • Counting rows. The header starts as one row. Each group label in it pulls in the row under it. If that row holds a group label too (a year over quarters), the next row comes in as well. The loop stops when nothing grows. More than maxRows (3) rows usually means a merge in the data, not a header, so it is refused.
  • Names. For each column, the code takes what Excel shows in each header row, from top to bottom, and joins the labels with a space. parts keeps the pieces (["Q1", "Revenue"]) if you prefer nested fields. A number used as a label, such as the year 2026, becomes text.
  • Checks. Three headers would give wrong names, so they are refused before any record is read (examples below): a merge over every column, which is a title, not a group; a group label with an empty cell under it; and a text value under no group label in a header row, which means a "group" was only a layout merge and that row is data.

Two more problems come back with the records, as in the one-row version: a name used twice, ignoring case (the same group label typed over two groups gives two "Q1 Revenue" columns), and a column with data but no name.

What this does not cover

  • Group labels typed once without a merge. If "Q1" is in C1 and D1 is just empty, there is no merge to read, so the header is one row. Filling "Q1" to the right would be a guess; ask the user to merge or repeat the label.
  • A layout merge over text data in every column it covers. If an Id column is merged down and "Contact" is merged over two text columns for looks, the first data row is read as names ("Contact Ana"). Show the column names in your preview so the user can catch it.
  • Notes beside the table. A note merged across two cells to the right of the header row is taken for a group label, so the file is refused with problems that point at the note. Ask the user to delete it.
  • CSV and .xls files, other sheets and hidden rows, as in the previous post.
