title: Read multi-row Excel headers with merged cells in SheetJS description: SheetJS reads one header row, so "Q1" merged over Revenue and Cost gives __EMPTY keys. Tested JavaScript that builds names like "Q1 Revenue" instead. date: 2026-11-27 ---

A customer uploads a sales report whose header has two rows: "Q1" is merged across two columns, with "Revenue" and "Cost" under it. SheetJS reads only the first row as column names, so you get keys like __EMPTY, and the second header row arrives as a record.

By the end of this post you will have readGroupedTable(bytes), about 190 lines that need only SheetJS. It works out how many rows the header has from its merged cells, names each column from top to bottom (Q1 Revenue, Q1 Cost), and refuses headers it cannot name safely, with the Excel address of the cell to fix. Every result quoted below is checked by our test file (the tests named mh:) in Node 22 with SheetJS 0.20.3.

How the code decides where the header ends

SheetJS lists the merged ranges of a sheet in its !merges array. The code calls a merge with text across two or more columns, like "Q1" over C1:D1, a group label. The columns under a group label need their own names, so the row under it belongs to the header too. If that row holds another group label (a year over quarters), the header grows again, up to a limit of three rows.

Any other text in the header is a plain label: "Region", even though it is merged down over A1:A2, names one column. An empty merge is layout and is ignored.

Step 1: read the sheet

readSheet returns every row as an array (defval: null keeps empty cells, blankrows: true keeps empty rows, so row indexes match the sheet) and turns each merge into row and column indexes. A sheet's stored range (its !ref) does not always start at A1, so both count from the start of that range, origin, and messages convert back to Excel addresses. The two helpers at the end are shared by the next steps.

Step 2: find the header rows

findHeaderRows grows the header from its first row until every group label has a row of names under it. Then it refuses shapes that would give wrong names for every column, in this order:

  • Title. A group label in the first row over every named column ("Sales 2026" over A1:C1) would start every name. The hint gives the Excel row of the first non-empty row under it, to pass as headerRow.
  • Too tall: more than maxRows rows (default 3), or a header that runs past the end of the sheet. The title check comes first, so a title over a tall header still gets the title hint.
  • A merge across the edge of the header. "Region" merged over A1:A3 in a two-row header would leave row 3's region empty.

It also refuses an empty first row and a headerRow outside the sheet.

{{code:MH_FIND}}

Step 3: name the columns

readHeader walks each column from top to bottom and joins the labels it sees with a space. A merge counts once however many rows it covers, and line breaks inside a cell become spaces. Then it checks the cells:

  • Text under a plain label. If a merge made for layout ("Note" over B1:C1) turns a one-row header into two rows, the first data row is read as names. Its tell: "Ana" sits under "Name", which is not a group label. Every such cell is reported.
  • Hole. A column under a group label with no name below it would be called just "Q1".
  • Same name twice. The second column would overwrite the first in every record. Names that differ only in case are refused too, because a column mapping that ignores case would mix them up.
  • No data under the header.
{{code:MH_HEADER}}

Each column also keeps parts (["Q1", "Revenue"]), if you would rather build nested fields than join the labels.

Step 4: read the records

readGroupedTable turns each row under the header into a record with the row number the user sees in Excel, so your error messages can point at it. It skips blank rows.

{{code:MH_TABLE}}

It does not fill merged cells in the data. "North" over A3:A4 is stored in A3 only, so Bo's Region is null; the function returns a note for each such merge instead of guessing. Our post on filling merged cells covers when copying the value down is safe.

Values come back as stored (raw: true), so dates in the data arrive as serial numbers; our post on reading Excel dates converts them. A sheet with many merges in the data gives one note per merge, so group them by column before you show them.

The "Total" over "Amount" refusal is a choice. From the cells alone it looks exactly like "Name" over "Ana", and reading a data row as column names is worse than asking the user to type one name.

What this does not cover

  • Labels that look merged but are not. Excel's Center Across Selection centers a label over several cells without merging them (UW-Madison KnowledgeBase, updated 2026-09-01). A label typed once over two columns with no merge is the same. There is no merge to read, so the header is one row: the sales report comes back with columns Region, Rep, Q1 and Q2, its first record is the Revenue row, and columns D and F get a "data but no name" note. Ask the user to merge the labels or type full names.
  • A group label over every column ("Contact" over First, Last and Email, with nothing beside it) looks exactly like a title, so it is refused. Importing with the suggested headerRow reads the names without "Contact".
  • A title over only some columns ("Sales 2026" over three of four names) is read as a group label: the names become "Sales 2026 Name". Pass headerRow if you know where the names start.
  • A layout merge over text data in every column under it, next to a column merged down, reads the first data row as names ("Contact Ana"). Show the column names in your import preview so the user can catch it.
  • A note merged beside the header is taken for a group label, and the file is refused with problems in that row.
  • Group labels stored as dates, such as "Jan 2026", arrive as serial numbers (46023 Revenue). Convert them as in our post on reading Excel dates.
  • Values hidden under a merge. An .xlsx file can store values in the covered cells of a merge (same SheetJS page). The code uses only what Excel shows, the top-left value, and ignores the rest.
  • Other sheets, hidden rows, and finding where the header starts. The code reads the first sheet and starts at its first row unless you pass headerRow; our post on finding the header row can supply it. CSV files have no merges, so they read as one-row headers.
