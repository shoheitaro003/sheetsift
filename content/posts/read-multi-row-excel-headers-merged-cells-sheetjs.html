title: Read multi-row Excel headers with merged cells in SheetJS description: SheetJS reads one header row, so "Q1" merged over Revenue and Cost gives __EMPTY keys. Tested JavaScript that builds names like "Q1 Revenue" instead. date: 2026-11-26 ---

A customer uploads a sales report whose header has two rows: "Q1" is merged across two columns, with "Revenue" and "Cost" under it. SheetJS reads the first row as the column names, so you get keys like __EMPTY, and the second header row arrives as a record.

By the end of this post you will have readGroupedTable(bytes): it finds how many rows the header has from its merged cells, names each column from top to bottom (Q1 Revenue, Q1 Cost), and refuses headers it cannot name with confidence, with the Excel address of the cell to fix. The code is not self-contained: it adds two functions to the module from our post on filling merged cells and uses its readXlsx, fillMerges, isEmpty and isLabel, which also handle merges in the data rows. Every result quoted below is checked by our test file (the tests named mh:) in Node 22 with SheetJS 0.20.3.

A merged range stores its value in its first (top-left) cell only, so D1 and F1 are empty and SheetJS invents __EMPTY names for them. Starting at row 2 loses "Q1" and "Q2" instead, and the two Revenue columns become Revenue and Revenue_1. Neither tells your column mapping which quarter a number belongs to.

Step 1: read the header

The merges tell you the shape of the header. A label merged across columns is a group label: it says that the columns under it share a name, so the row under it must be part of the header too. A label merged down, like "Region" over A1:A2, just fills the header's height and counts once in the name. A merge with no value is layout, and is ignored.

What the four parts do, and why:

  1. Counting rows. The header starts as one row. Each group label in it pulls in the row under it, because a group needs names under it. If that row holds a group label too (a year over quarters), the next row comes in as well. The loop stops when nothing grows. We cap the header at maxRows (3) rows, enough for year, quarter and measure, so that a stray merge cannot swallow data rows into the header.
  2. Names. For each column, the code takes what Excel shows in each header row, from top to bottom, and joins the labels with a space. parts keeps the pieces (["Q1", "Revenue"]): use them as the key if you build nested fields, because a joined name can clash with a one-row name such as Q1 Revenue (the duplicate check in step 2 reports that). A number used as a label, such as the year 2026, becomes text.
  3. Checks. Some headers would give wrong names, so they are refused before any record is read: a merge over every named column (read as a title), a group label with no name under one of its columns, a value under a plain label in a lower header row, and a header with no data rows under it. Each problem has a range, a short reason and a hint for the user, and refuse: true.
  4. Hidden values. A value stored in a cell that a merge covers, such as an old name in D1 under "Q1", is not shown by Excel and is not used in any name. It is reported, as for merges in the data, but the file is still read.

The third check needs a word on why. In a lower header row, a value may sit under a group label, or under empty cells (a name aligned to the bottom row, like "Region" in A2 with A1 empty). A value under a plain label, such as "Ana" under "Name", means the row is really data, and the merge that pulled it into the header is a title or just layout. The code checks every cell of the row, so the user sees all of them at once.

The same check refuses a label over a single column with a name under it, such as "Total" over "Amount" next to a merged group. We chose to refuse it: from the cells alone, "Total" over "Amount" has the same shape as "Name" over "Ana", and reading a data row as names would be worse than asking the user to type "Total Amount" in one cell.

headerTop is a row index, not an Excel row number: 0 is the first row SheetJS reads (row 1 for most files), 1 the row under it. Merges that start in the header and run into the data, such as "Region" over A1:A3 in a two-row header, are reported by fillMerges. With a one-row header and no group labels, the result is the same as readMergedTable from the previous post (a test checks this).

Three more problems come back with the records, without refuse: a value hidden under a header merge, a name used twice ignoring case (the same group label typed over two groups gives two "Q1 Revenue" columns), and a column with data but no name. The last two point at the column's header cells, such as D1:D2.

What this does not cover

  • Group labels typed once without a merge. If "Q1" is in C1 and D1 is just empty, there is no merge to read, so the header is one row. Filling "Q1" to the right would be a guess; ask the user to merge or repeat the label.
  • Labels centered with "Center Across Selection". This Excel alignment centers a label over several cells without merging them (UW-Madison KnowledgeBase, updated 2026-09-01); the file stores it as the centerContinuous alignment (Microsoft's MS-EXSPXML spec, last updated 2020-10-13). There is no merge to read, so the header is one row: on the sales report, the code returns the columns Region, Rep, Q1 and Q2, and reports D1 as a column with data but no name. Ask the user to merge the labels or type full names.
  • A layout merge over text data in every column it covers. If an Id column is merged down and "Contact" is merged over two text columns for looks, the first data row is read as names ("Contact Ana"). Show the column names in your preview so the user can catch it.
  • A real group over every column. "Contact" over First, Last and Email in a three-column table is refused as a title. Passing headerTop 1 reads the names without "Contact".
  • A title over only some columns. "Sales 2026" merged over A1:C1 above four names is read as a group label, so the names start with it ("Sales 2026 Name"), with no problem reported. If you know where the names are, pass headerTop; either way, show the column names in your preview.
  • Data right of the last named column is not read, and no problem is reported, as in the previous post.
  • Group labels stored as dates. A month label such as "Jan 2026" is stored as a number with a date format, so it arrives as 46023 and the names become 46023 Revenue. Convert it as in our post on reading Excel dates, or ask the user to type the label as text.
  • Notes beside the table. A note merged across two cells to the right of the header row is taken for a group label, so the file is refused with problems that point at the note. Ask the user to delete it.
  • CSV and .xls files, other sheets and hidden rows, as in the previous post.
